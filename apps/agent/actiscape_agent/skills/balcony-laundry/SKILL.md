# 生活阳台与家政

> v1 接入说明：本 Skill 只声明语义 capability，不能直接写正式场景、提交项目或执行任意脚本。所有修改必须形成候选，并由固定代码预检、渲染、审核和提交。

## 什么时候用

✅ 适用：

- 生活阳台/家政阳台，使用面积 1.2–6㎡，已有一版含墙体、窗与推拉门的场景；
- 用户要把洗衣机/烘干机搬上阳台、要加洗衣池、要装晾衣杆；
- 已有旧阳台，想在不动排水立管的前提下重排。

❌ 不适用（转其他技能）：

- 需要改排水立管、楼板开洞、加装地漏：超出本技能 [J-VER-01]；
- 封阳台、改窗、做结构加固：先走 `floorplan-intake` 补结构信息；
- 纯景观阳台（不洗衣、只休闲）：转 `living-dining-open` 或 `style-coherence`；
- 需要增加热水点位（阳台洗手/洗衣用热水）：超出本技能。

开工前只问三件事（问不到就按保守值）：

1. 阳台有没有**专用排水**与地漏、地漏有没有存水弯（决定洗衣机能放哪一端）；
2. 洗衣机和烘干机是**叠放**还是**并排**（叠放省地但要够高，并排要够宽）；
3. 阳台朝西还是朝北、有没有封窗（决定防晒、防冻与烘干机选型）。

## 怎么做

**第 1 步 · 先定排水，再定机器位置**

- 洗衣机排水必须接**专用地漏或立管接口**，不能和地面地漏共用一个——共用一定返水；
- 地漏要有存水弯，否则整间会有下水味；
- 阳台地面要有坡向地漏的找坡，机器脚下做 50–100 的垫高（防潮、防泡）；
- 排水在远端时，先算排水管长度与坡度，再决定机器摆哪一头，不要反过来。

**第 2 步 · 叠放还是并排（第一个取舍）**

| 方式               | 占地          | 前提                                 | 代价                             |
| ------------------ | ------------- | ------------------------------------ | -------------------------------- |
| 叠放（烘干机在上） | 一台的宽 × 深 | 阳台净高够、有叠放架、机器同品牌可叠 | 上机取放要踮脚；烘干机不能太重   |
| 并排               | 两台的宽      | 开间够，且两台都能开门               | 吃掉一整面墙，晾衣区被压缩       |
| 并排 + 上方台面    | 两台的宽      | 同上，且台面要能承重                 | 台面高度按洗衣机定，水槽只能做浅 |

判断顺序：先量净高（叠放要看吊顶与晾衣杆），净高不够就并排；并排放不下就只留一台，另一台换洗烘一体——**不要为了两台机器把通道压到不能站人**。

**第 3 步 · 洗衣机前的操作面** [J-BAL-01] [J-CIR-01]

- 机器前要留出开门、放取衣物、蹲下的空间 [J-BAL-01]；
- 前开门的机器门是往外开的，门前这块不能放洗衣篮、脏衣篓；
- 机器侧面的检修空间也要留（至少一侧能伸手），不要三面贴死；
- 阳台进深不足时，把机器放在**短边**（门在一侧），而不是长边中间。

**第 4 步 · 洗衣池（要不要做）**

- 做：手洗小件、泡鞋、接水拖地都要用；池深 200 以上、龙头能转向；
- 不做：把池的位置换成台面 + 脏衣篮，但要有"临时接水"的替代（否则会去卫生间端水）；
- 洗衣池不要放在晾衣杆正下方（滴水会溅到池里）。

**第 5 步 · 晾衣杆：高度与长度** [J-BAL-01]

- 杆底离地按 [J-BAL-01] 的高度，低于它大衣拖地、走人碰头；
- 杆长按一次洗衣量估：一家三口一次约 12–16 件，杆长 1.4–1.8m 起步，双杆比单杆实用；
- 电动晾衣架的机身要有位置，不能和吊柜、窗帘盒打架；
- 杆不要正对推拉门（进门先撞一杆衣服），要退到阳台内侧 [J-DOOR-01]。

**第 6 步 · 储物吊柜与晾衣杆的冲突**

- 吊柜底离地 1400 以上，且要**避开晾衣杆的升降路径**；
- 吊柜不要做在洗衣机正上方（开门取物会撞头，也挡检修）；
- 阳台有窗时，吊柜不进窗洞范围，窗前按 [J-CUR-01] 让开窗帘活动区；
- 储物优先做"窄高柜"（放洗衣液、拖把），比做一排吊柜更实用。

**第 7 步 · 与客厅的隔断/推拉门避让** [J-DOOR-01]

- 通客厅的推拉门/折叠门前按 [J-DOOR-01] 让开，不能放机器、柜子、晾衣杆；
- 门扇是推拉的，轨道那一侧不要有地垫、门槛石凸起；
- 想做隔断时，优先"玻璃推拉 + 门帘"，不要砌死墙——阳台的采光要还给客厅；
- 隔断不要做到顶，留出 100–200 的回风缝，否则阳台潮气进不来也出不去。

**第 8 步 · 分批提交与检查**

1. 先提交洗衣机、烘干机、洗衣池，`candidate.propose + candidate.preflight` 带 `base_version`、`op_id` 唯一；
2. `candidate.preflight / candidate.review` 看推拉门前 400、重叠、窗内侧 150；
3. 再提交晾衣杆、吊柜、绿植，再检查；
4. 最多 3 轮修复 [J-VER-02]；放不下时按"先保机器与排水、再保晾晒、最后保储物"的顺序砍；
5. 只改本次涉及的家电与柜体，户型与无关家具不动 [J-VER-01]。

与原项目 Skill 的差异：原流程把阳台当"放得下就行"的边角空间，本技能把**排水 → 机器 → 晾晒 → 储物**写成固定顺序：排水决定位置，位置决定通道，通道决定还能不能晾衣服。

未适配时的降级路径（状态仍为 `pending_adaptation`）：

- 没有 `scene.*`：输出"机器与柜体坐标 + 三条净空 + 排水口位置"的文字表，交主控转场景；
- 没有 `candidate.preflight / candidate.review`：按第 3、5、7 步的判据人工核算，交付里注明"未经工具检查"。

## 怎么验证

- **正向** `BAL-dev-01`：1.6 × 3.2m 生活阳台（5.12㎡，< 6㎡）。洗衣机与烘干机并排贴南墙（前方净空 1800），洗衣池贴东墙、晾衣杆（吸顶）沿长边、绿植靠西墙，推拉门在北墙。期望 `candidate.preflight / candidate.review` 全通过：推拉门前 400 内无家具、窗内侧 150 内无高家具、无重叠。
- **边界** `BAL-dev-02`：同一个阳台，把洗衣机和烘干机并排怼在推拉门正后方（"进门就是洗衣机"）。期望报 `DOOR-01`——推拉门打不开也走不了人，技能要拒绝并把机器退回南墙。

两个案例都在 `examples/` 下，`ops.json` 可被 mock 引擎复跑；L1 结构与 L2 几何结果记录在 `manifest.validation`。
