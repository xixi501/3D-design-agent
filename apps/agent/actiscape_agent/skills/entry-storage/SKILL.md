# 玄关与入户收纳

> v1 接入说明：本 Skill 只声明语义 capability，不能直接写正式场景、提交项目或执行任意脚本。所有修改必须形成候选，并由固定代码预检、渲染、审核和提交。

## 什么时候用

✅ 适用：

- 玄关使用面积 1.5–6㎡，已有一版含入户门与墙体门窗的场景；
- 用户说"进门太乱""鞋放不下""换鞋没地方坐""玄关要不要做隔断"；
- 已有旧玄关，想在不拆墙的前提下加柜、换布局。

❌ 不适用（转其他技能）：

- 需要拆改墙体、扩大门洞、改入户门位置：超出本技能 [J-VER-01]；
- 要做整墙定制柜的结构与板材深化：本技能只定位置与尺寸，不做柜体结构；
- 玄关与餐厅/客厅完全打通、没有独立入户区：转 `living-dining-open`；
- 适老化（扶手、坐凳高度、无高差入户）：转 `aging-friendly`。

开工前只问三件事（问不到就按保守值）：

1. 常住几口人、有没有小孩/老人（决定鞋柜容量与换鞋凳高度）；
2. 入户门是内开还是外开、门后有没有墙垛（决定哪一面墙能用）[J-ENT-01]；
3. 强弱电箱在哪面墙、离地多高（决定这面墙能不能做通高柜）。

## 怎么做

**第 1 步 · 先画动线，再放柜子**
入户动线是一条单向的五段：**开门 → 落尘 → 换鞋 → 挂衣 → 镜**。

- 顺序不能倒：先换鞋再挂衣，人才不会一只脚站着脱外套；
- 五段要沿**同一侧墙**排开，让另一侧留出通道 [J-CIR-01]；
- 如果只能排三段，砍掉"镜"和"挂衣"，不要砍"换鞋"。

**第 2 步 · 定鞋柜深度与容量（先算容量，再定柜长）** [J-ENT-01]

- 深度按 [J-ENT-01] 的鞋柜深度，不要为了"能放鞋盒"做成 450——多出的 100 会直接吃掉通道；
- 容量估算：每人按 8–12 双估（当季 + 换季），1m 宽 × 通高的鞋柜约 20–24 双；
- 算例：三口人 ≈ 30 双 → 需要 1.4m 宽的通高柜，或 1.0m 通高 + 一处换季顶柜；
- 柜内净高按鞋型分：平底鞋 120、运动鞋 150、短靴 250、长靴 400；层板做可调，不要一次钉死。

**第 3 步 · 换鞋凳前净空** [J-ENT-02]

- 凳子前要留出弯腰、起身、放包的空间 [J-ENT-02]；凳子进深 350–400，高度 400–450；
- 凳子不要正对入户门扇——门一开就撞人 [J-ENT-01]；
- 地方不够时，把换鞋凳做成**柜内抽拉凳**或翻板凳：坐的时候拉出，平时收进柜体。

**第 4 步 · 强弱电箱不被遮挡**

- 先量箱体位置与高度，箱子所在的那一格必须**能开、能检修、能散热**；
- 做法：柜体在这一格断开、做活动层板或独立小门；箱体下方不做高柜；
- 绝对不要把箱子封进柜体背板——检修时要拆柜，物业也不会同意；
- 箱子在 1.4–1.8m 高时，正好落在"挂衣区"的高度，把挂衣区让开它就行。

**第 5 步 · 落尘区材质**

- 入户 1–1.2m 内做落尘区：地垫、石材或六角砖，与室内地面做 5–10mm 高差（或至少不同材质分界）；
- 不要全屋通铺：鞋底带进来的沙会一路带到客厅，通铺的地板两年就花；
- 落尘区要"能扫能吸"：长毛地垫好看但藏沙，入户优先短毛或刮泥垫；
- 落尘区范围 = 门扇开启区 + 一步的距离，不要做得比门洞还小。

**第 6 步 · 镜与挂衣**

- 镜放在动线末端（换完鞋、穿好外套之后照），不要放在门后（开门挡住）；
- 挂衣钩高度按最长外套 + 100 留，下面留出包/伞的位置；
- 玄关有窗时，窗前按 [J-CUR-01] 让开窗帘活动区，窗下只能放矮柜，不能做通高柜。

**第 7 步 · 地方不够时先保什么（本技能的核心取舍）**

保住顺序，从高到低：

1. 入户门扇开启后的净宽 [J-ENT-01] —— 保不住这一条，方案直接不成立；
2. 换鞋凳前净空 [J-ENT-02] —— 坐着换鞋是玄关唯一的"刚需动作"；
3. 鞋柜深度 350 的通高柜 [J-ENT-01] —— 容量不够会立刻反弹成"门口一堆鞋"；
4. 挂衣与包的位置 —— 可以用门后挂钩、墙面挂杆替代；
5. 落尘区的高差与材质 —— 可以用地垫降级；
6. 镜、换鞋凳的造型、装饰 —— 最后才谈。

面积 < 2㎡ 时：鞋柜做 350 深通高柜 + 中段留空做换鞋位（柜内抽拉凳），镜贴在柜门上，挂衣用柜侧挂钩。宁可"一段通高柜"也不要"三件小家具"。

**第 8 步 · 分批提交与检查**

1. 先提交鞋柜与换鞋凳，`candidate.propose + candidate.preflight` 带 `base_version`、`op_id` 唯一；
2. `candidate.preflight / candidate.review` 看门扇扫掠、窗帘活动区、重叠；
3. 再提交镜、挂衣、地垫，再检查；
4. 最多 3 轮修复 [J-VER-02]；放不下时按第 7 步的顺序砍，不要缩门扇净宽；
5. 只改本次涉及的家具，户型与无关家具不动 [J-VER-01]。

## 依赖什么

| 工具                                      | 用途                                        | 状态    |
| ----------------------------------------- | ------------------------------------------- | ------- |
| `catalog.search`                          | 取鞋柜、换鞋凳、镜、挂衣杆的 key 与默认尺寸 | 可 mock |
| `scene.read`                              | 读入户门朝向、门扇开启方向、墙面与电箱位置  | 待成员1 |
| `candidate.propose + candidate.preflight` | 提交增删改，带版本与幂等                    | 待成员1 |
| `candidate.preflight / candidate.review`  | 门扇扫掠、窗帘活动区、重叠                  | 可 mock |

与原项目 Skill 的差异：原流程偏向"出一张玄关效果图"，本技能把**容量估算与保住顺序**写成可复核的步骤——先算要放多少双鞋，再决定柜子多长；先保门扇与换鞋位，再谈好看。

未适配时的降级路径（状态仍为 `pending_adaptation`）：

- 没有 `scene.*`：输出"柜体坐标 + 门扇开启区 + 容量估算表"的文字方案，交主控转场景；
- 没有 `candidate.preflight / candidate.review`：按第 2、3 步的判据人工核算，交付里注明"未经工具检查"。

## 怎么验证

- **正向** `ENT-dev-01`：1.8 × 2.6m 玄关（4.68㎡，< 6㎡）。鞋柜 1200 × 350 贴东墙（柜前净宽 1250），换鞋凳 900 × 350 贴北墙（凳前 1250），穿衣镜贴西墙，落尘垫 900 × 600 落在门扇内侧。期望 `candidate.preflight / candidate.review` 全通过：门扇 900 × 900 扫掠区无家具、门口有落脚点、无重叠。
- **边界** `ENT-dev-02`：同一个玄关，把鞋柜横在门扇扫掠区里（"进门顺手放鞋"）。期望报 `DOOR-02`——门打不开，技能要拒绝并把柜子退回东墙，同时给出"窄玄关先保通"的替代。

两个案例都在 `examples/` 下，`ops.json` 可被 mock 引擎复跑；L1 结构与 L2 几何结果记录在 `manifest.validation`。
