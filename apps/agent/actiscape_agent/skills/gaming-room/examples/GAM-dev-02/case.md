# GAM-dev-02 · 想借光，把桌子推到东窗下（边界／失败）

## 输入

同一个 3000 × 3800 电竞房，东墙窗 1200（窗台 800），南墙门 900（距西端 1900）。

## 用户／错误做法

"白天想借自然光，桌子干脆贴着东窗放，屏幕朝西，窗就在背后，抬头还能看外面。"

## 技能应如何拒绝

1. **窗在屏幕背后 = 背光最差**：窗光从屏幕后方射来，屏幕上全是人像与窗框的反光，白天要拉满遮光帘，
   等于把"借光"变成"把光全挡住"——这一条按 [J-LIGHT-05]，是人工判断，引擎不查。
2. **桌子占住窗内侧 150 的窗帘活动区**：表面前沿顶到窗墙，窗帘落不下来、开不了窗，属 [J-CUR-01]。
   引擎会直接拦：桌深 700 + 窗台 800 < 桌高 750，桌面高过窗台且压在 150 带内。
3. 替代方案（按优先序）：
   - 桌子回到北墙（现状 GAM-dev-01），窗仍在右侧，侧光；
   - 或者桌子留东墙但整体南移，桌面离窗墙内皮 ≥600，把窗前 600 让给窗帘与开窗；
   - 无论哪种，**椅子后推 900 与门弧 900 都不能让**。

顺带说明为什么"背窗"不如"侧窗"：屏幕面与窗面成 90° 时，窗光只照到侧脸与桌面边缘，
不会在屏面形成镜面反射；成 0°（背窗）时，屏面正对光，反射最严重 [J-LIGHT-05]。

## 判定

`check.run` 应 `pass = false`：报 `CUR-01`（窗内侧 150 内有 h>600 的落地家具 `o_desk`）。
门扇、重叠、支撑、柜体挡窗都应仍然通过——本案例只演示"桌面顶窗"这一个错。
