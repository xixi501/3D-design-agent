# HOF-dev-02 · 9.5㎡ 书房（边界：打印机搁在桌角，超出桌面）

## 输入

- 场景与 HOF-dev-01 相同（3000 × 3600，北窗 1600，东门 900）。
- 现有：书桌 1200×600（x 900–2100、y 450–1050）、办公椅、书架（东墙）。
- 用户原话："打印机也放桌上吧，就摆在右手边角上，反正桌上空着。"

## 已知约束

- 打印机 650×650×1100，桌面 1200×600、面高 750；
- 桌面上的物件必须完整落在桌面范围内，不许悬空、不许骑边 [J-ASSET-02]；
- 视频背景要保持干净，不能因为加设备把桌子变成杂物台；
- 书桌、椅子、书架的位置不动，只加一件设备。

## 技能给出的方案（错误示范，应被拒绝）

```json
{
  "op": "add",
  "object": {
    "id": "o_printer",
    "key": "printer",
    "at": [1900, 700],
    "rot": 0,
    "on": "o_desk",
    "w": 650,
    "d": 650
  }
}
```

`on` 写对了（确实声明了支撑物），但中心 (1900, 700) 让打印机的包围盒落到
x 1575–2225、y 375–1025——东侧超出桌面 125，北侧又悬出 75。
再加上打印机本身高 1100、比桌面高出 350，它其实不是"台面件"，而是"落地件"。

## 判定

`check.run` 必须报 `ASSET-02`，`pass = false`：台面物件超出支撑物范围。

技能的正确反应（三条都可以）：

1. 打印机下地：放在文件柜上或单独的打印机架（落地件，`on` 去掉），
   位置选在西墙文件柜所在的角落，视频画面之外；
2. 换尺寸：桌面只留 ≤ 桌面进深一半的一体机，或改成抽屉式打印托盘；
3. 明确拒绝：桌面 1200×600 上放 650 深的机器，写字的余量不够，
   这属于"空间不够"而不是"摆法不对"，按 `E_CONSTRAINT_UNSATISFIABLE` 处理。

不要用"往中间挪 100 就能塞下"来收尾——那样虽然过了检查，桌面就只剩 550 宽可用。
