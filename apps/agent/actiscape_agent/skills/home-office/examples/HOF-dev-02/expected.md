# 边界案例要证明什么

1. 写了 `on` 不等于放对了——支撑关系的判定是几何包含，不是字段声明；
2. 只错一件、只报一条，边界案例要能定位到具体对象（`o_printer` / `o_desk`）；
3. 修复方向是"换支撑"或"换尺寸"，不是"一点点挪到勉强过"——后者会让桌面失去使用价值。

# 失效即表示

- 没报 `ASSET-02`：支撑包含判定（含 ±10 容差）被改动，或 `on` 字段没被读取；
- 同时报了 `OVER-01`：说明 `on` 关系的跳过逻辑失效，先把这一对排除；
- 报了 `CUR-01`：打印机被放到了窗带里，坐标错得比预期多。
