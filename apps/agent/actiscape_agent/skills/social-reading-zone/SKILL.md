# 会客 + 阅读的功能分组与局部调整

> v1 接入说明：本 Skill 只声明语义 capability，不能直接写正式场景、提交项目或执行任意脚本。所有修改必须形成候选，并由固定代码预检、渲染、审核和提交。

## 什么时候用

✅ 适用：

- 客厅已有一组会客家具（沙发/茶几/地毯/电视柜），用户只要求加或改一个阅读角；
- 用户明确说"别动沙发""只改这一块"——这正是最小改动的入口 [J-VER-01]；
- 场景里有实墙角落可用，且能从门口或会客区走过去。

❌ 不适用（转其他技能）：

- 要重排整间客厅、换沙发或改主墙：转 `living-dining-small` 或 `living-dining-open`；
- 阅读角要兼书房（书桌 + 屏幕）：转 `home-office`，判据与净空口径都不同；
- 需要改墙体、门窗、插座点位：超出本技能，交回主控 [J-VER-01] 的边界也一样。

开工前只问三件事：

1. 谁用这个角、用来做什么（看书/看手机/和孩子读绘本）——决定椅型与边几高度；
2. 有没有一盏可移动的落地灯（没有就先买灯，再定位置）；
3. 原来那组家具里，哪些是"绝对不能动"的（这句话决定本次的编辑范围）。

## 怎么做

**第 1 步 · 先分组，再动手**
`scene.read` 取当前版本与对象清单，用 `{"op":"group","name":"会客组","ids":[...]}` 把现有对象声明成组，
再声明一个空的"阅读组"。分组不是装饰：它是本次编辑范围的书面边界，后面每一步都要问"这个 id 在不在目标组里"。
不属于目标组的对象，一个坐标都不改 [J-VER-01]；最后用 `candidate.review` 把这条证明落成证据。

**第 2 步 · 阅读角选址（三选一，按优先级）**

| 位置                              | 优点                         | 代价                 | 什么时候选它               |
| --------------------------------- | ---------------------------- | -------------------- | -------------------------- |
| 窗侧角（背靠侧墙、窗在左/右前方） | 白天不用开灯，侧光不刺眼     | 离窗太近会顶到窗帘   | 主沙发不在窗前时优先       |
| 沙发侧后方（沙发同侧延伸）        | 与主沙发共享对话区，动线最短 | 沙发靠墙时空间不够   | 沙发背后或侧边有 ≥700 空档 |
| 书架墙侧（靠实墙）                | 拿书方便，围合感最好         | 没有自然光，必须补灯 | 只能给人工照明时           |

判断顺序：先排"窗侧角"，再看"沙发侧后"，最后才用"书架墙侧"。贴窗时必须让阅读椅与书架都退出窗的
内侧带 [J-CUR-01]、退出窗前高柜带 [J-WIN-01]——"靠窗阅读"不等于"把家具堆在窗下"。

**第 3 步 · 三件套的三角关系**

- 椅：单人椅或阅读椅（背高一点的更聚气），背靠墙角或侧墙，朝向厅内；
- 灯：落在椅的**侧后方**，不要正前方；灯头高度大致与坐姿眼高齐平，人坐下后手能够到开关；
- 边几：落在椅的一侧，上沿高于扶手一点，抬手就能放杯子；
- 边几与椅允许轻微互压（这是 [J-OVER-01] 的允许例外），灯与椅、灯与几必须完全分开——灯是热源，也是绊倒点。

**第 4 步 · 书架（可选，但要按柜子的规矩放）**
书架只能靠实墙，且必须退出窗的 400 带（高柜挡窗）[J-WIN-01]；
高度超过 600 的书架不许站在窗内侧带里，否则窗帘拉不动 [J-CUR-01]；
书架的正面要有拿书的空间（人站得住、蹲得下去），这一条靠第 5 步的组内通道一起核。

**第 5 步 · 组内通道与出入口（半围合，不是围死）**
阅读角要做成"半围合"：背后有墙、侧面有家具，但必须留**一个**开口与外面连通，宽度按 [J-CIR-01] 的主通道值取。
判断方法：从阅读椅站起来，能不能不侧身、不跨过任何家具走到会客区；再从入户门走一遍 [J-CIR-02]。
整个房间的主通道不得从沙发与茶几之间穿过 [J-LAY-01]，阅读角也不能把主通道挤成"必须绕着走"的窄缝。

**第 6 步 · 与会客组的关系（不动它，但要让开它）**
沙发到茶几的间距属于会客组内部关系，不要为了塞阅读角去改它 [J-CIR-07]；
地毯是否覆盖到阅读椅，按"阅读椅至少前腿在地毯上"处理，不足时加一块小地毯而不是拉大主地毯 [J-PROP-02]；
新增家具的造型与颜色跟会客组同一套语言，阅读角不要再造第二个视觉焦点 [J-STY-03]。

**第 7 步 · 光（阅读角最容易糊弄、也最容易被投诉的一项）**
环境光 + 任务光两层：顶面仍要有基础照明，落地灯负责阅读面照度 [J-LIGHT-01]；
阅读面照度按 [J-LIGHT-02] 的阅读档取值，晚间色温按 [J-LIGHT-03] 的暖档，不要用一盏 4000K 以上的冷白灯照脸。

**第 8 步 · 提交与检查**

1. 先提"阅读组三件套"，`base_version` 用第 1 步的快照版本，`op_id` 唯一；
2. `candidate.preflight / candidate.review` 看遮挡、重叠、连通，再补书架；
3. 只改被点到的对象；自动修复最多 3 轮 [J-VER-02]，仍不过的如实报告，不假装成功；
4. 最后 `candidate.review` + 一帧 `candidate.render` 作为"只动了阅读组"的证据。

## 依赖什么

| 工具                                      | 用途                                           | 状态    |
| ----------------------------------------- | ---------------------------------------------- | ------- |
| `scene.read`                              | 取对象清单与版本，确认哪些属于会客组           | 待成员1 |
| `candidate.propose + candidate.preflight` | 提交 group / add / move / rotate，带版本与幂等 | 待成员1 |
| `candidate.review`                        | 证明本次只改了目标组 [J-VER-01]                | 待成员1 |
| `candidate.preflight / candidate.review`  | 遮挡、重叠、连通、支撑                         | 可 mock |
| `catalog.search`                          | 取椅/边几/落地灯/书架的 key 与尺寸             | 可 mock |
| `candidate.render`                        | 出图作为验收证据                               | 待成员1 |

未适配时的降级路径（状态仍为 `pending_adaptation`）：

- 没有 `group` 能力：在交付里贴一张"分组清单"表（会客组 4 件 / 阅读组 4 件），并且只对阅读组写坐标；
- 没有 `candidate.review`：把改动前后的对象清单并排贴出来，逐条标注"未改"，人工核对；
- 没有 `candidate.preflight / candidate.review`：按第 3、5 步的净空与连通逐条手算，并注明"未经工具检查"。

## 怎么验证

- **正向** `SRZ-dev-01`：4500 × 6000 的客厅（内净约 24.9㎡），会客组原样保留（沙发背靠西墙、
  电视柜背靠东墙），在东北角新增阅读组（阅读椅 + 边几 + 落地灯 + 书架）。期望 `candidate.preflight / candidate.review` 全通过，
  且 `candidate.review` 只出现 4 个 added、没有 changed。
- **边界** `SRZ-dev-02`：用户要求"把书架挪到窗下面去"，`move` 后书架压进窗内侧带。
  期望同时报 `CUR-01` 与 `WIN-01`，技能应拒绝并给出"书架留东墙 / 换矮柜"的替代。

两个案例都在 `examples/` 下，`ops.json` 可被 mock 引擎复跑；L1/L2 结果按 `VERIFY.md` 的口径记录。
