# 预期结果

- `check.run`：**pass = false**。
- `must_trigger`：`CUR-01`（[J-CUR-01]）与 `WIN-01`（[J-WIN-01]）。
- 期望同时不出现：`OVER-01`（书架移走后不与地毯/沙发重叠）、`DOOR-02`（离南门 2.8m 以上）。
- 实测信息：`窗 win1 前 150mm 内有 h>600 的家具 o_shelf(bookshelf)` 与
  `窗 win1 前 400mm 内有高柜 o_shelf(bookshelf, h=2000)`。

# 边界案例要证明什么

1. "靠窗更亮"是常见但错误的需求解读：窗下是高柜的死区，两个检查码会同时拦住；
2. 这两个码要同时出现——只报一个说明引擎的窗带深度写错了（150 与 400 是两层不同的带）；
3. 拒绝之后要有出路：书架回东墙（本案例原位），或用 h<窗台 的矮柜替代高书架，
   两种都不需要用户让步"采光"。

# 失效即表示

- 只报其中一个码：窗内侧带与窗前柜带的判定深度被合并了，先查引擎；
- 报 `OVER-01`：说明 `move` 的目标坐标算错，书架压到了别的东西上；
- 两个码都没报：窗洞口坐标或窗台高读错（本例 sill=600，h=2000 必然超过）。
