# 茶室 / 静区

> v1 接入说明：本 Skill 只声明语义 capability，不能直接写正式场景、提交项目或执行任意脚本。所有修改必须形成候选，并由固定代码预检、渲染、审核和提交。

## 什么时候用

✅ 适用：

- 使用面积约 4–10㎡ 的独立茶室，或客厅/书房里划出的一块静区；
- 用户要"一个人喝茶、看书、发呆"，或"偶尔两个人对坐聊天"；
- 已有一版含墙体与门窗的场景，或户型图已解析成场景。

❌ 不适用（转其他技能）：

- 要待客六人以上、需要围坐大桌：转 `social-reading-zone`（会客 + 阅读的功能分组逻辑不同）；
- 要做地台、榻榻米：先走 `tatami-multipurpose`，再回到本技能定茶席；
- 需要给排水、地暖、防水改造：超出本技能，交回主控并说明原因；
- 需要拆墙、改门窗：超出本技能。

开工前问三件事（问不到就按保守值）：

1. 一个人用还是两个人对坐（决定茶台 1200 还是 900）；问不到按两人对坐的 1200 做；
2. 坐着的时候主要看什么——窗外、墙上的画、还是对面的人（决定朝向）；
3. 要不要烧水（决定水吧位置与插座，不是平面几何能解决的，要单独标出来交电工）。

## 怎么做

**第 1 步 · 选位置：安静性优先于面积**
静区要放在主动线之外：从入户门走到客厅、厨房、卫生间的路径不穿过它 [J-CIR-01 的通行口径]。判断方法很直接——把家里"一定会走"的两条线画出来（入户→客厅、入户→厨房），茶席不压在这两条线上。挤在动线上的"茶室"最后会变成放杂物的过道。

**第 2 步 · 定坐席朝向（本技能的核心判断）**

- **不对门**：门在坐席视线正前方，人一进门就先看到你，茶席一直被打断；
- **不背窗**：背窗坐是逆光，对面的人只看得到剪影，自己也会被窗外的动静牵走；
- 两条都满足不了（小房间常见）时，退一步：**坐席侧对门、窗在侧前方**，让门在余光里、窗在侧向；
- 坐席背后要靠实墙（或高柜背板），背后是通道会一直有人从身后走过。

**第 3 步 · 一桌两椅一柜（最小配置）**

| 件           | 尺寸                                   | 说明                                             |
| ------------ | -------------------------------------- | ------------------------------------------------ |
| 茶台         | 1200 × 650（两人）或 900 × 650（一人） | 台面要放得下壶、公道、两只杯，还要留出出汤的位置 |
| 椅           | 460 × 520 × 2                          | 有扶手的椅子更稳，但要算扶手的宽度               |
| 茶器柜       | 900 × 350                              | 靠墙放，柜门/抽屉朝通道                          |
| 水吧（可选） | 500 × 500 边几                         | 烧水壶、水盂；离座位一臂内，但不占茶台面         |

先摆这三件，再谈软装。四件以上（再加一张边几、一个花器）在 6㎡ 以下就会挤掉通道；挤不下的表现不是"难看"，而是两件家具投影重叠 [J-OVER-01]，或者通道掉到 700 以下 [J-CIR-01]。这时要砍件，不是"挤一挤"。

**第 4 步 · 茶台与座位的间距**

- 座椅前沿到茶台边缘按对话距离控制，与客厅"沙发—茶几"同一口径 [J-CIR-07]；
- 椅子拉开后，台边到墙/柜还要能过人 [J-CIR-01]（小空间最低 700，能到 900 更好）；
- 茶台横在房间正中、四周各留一点"看起来对称"的摆法，最容易把通行压到 700 以下——桌要靠一侧，把通道整条留出来。

**第 5 步 · 矮家具与地台的高度配套**

- 坐垫 + 矮台（台面 400 上下）是一套；椅子 + 常规台面（700 上下）是另一套，两套不要混；
- 做地台时按 `tatami-multipurpose` 的口径处理台高、门扇与窗；茶席只负责台面上的家具；
- 矮台的台面低于窗台时才能贴窗放，否则窗扇、窗帘都会被台面顶住。

**第 6 步 · 储物：茶器与水吧分开**

- 茶器柜放"坐着伸手够不到、站起来一步能到"的位置，柜内按"常用在上、备用在下"分层；
- 水吧要有独立台面与插座（烧水壶功率大，不与照明同回路——这条交电工，不在平面里解决）；
- 柜子长度不超过所在墙面长的 2/3，超过就拆成两段，否则墙面会被柜子压死。

**第 7 步 · 光与色（静区的"好看"条件）**

- 照明分层：环境光打底 + 茶台上方一盏重点光，不要只有一盏顶灯 [J-LIGHT-01]；
- 照度按会客/阅读口径取，看茶样、看书时在局部补到阅读档 [J-LIGHT-02]；
- 配色按主色/辅色/点缀的比例分配，木色与织物色控制在同色系 [J-COL-01]；
- 一个空间只留一个视觉焦点（一面造型墙、一个壁龛或一盏灯），其余退到背景 [J-STY-03]。

**第 8 步 · 提交与检查**

1. 先提交茶台与两把椅子，`candidate.preflight / candidate.review` 看通道与门口连通 [J-CIR-02]；
2. 再提交茶器柜与水吧，检查柜前与座位后是否还能过人；
3. 最后加地毯、窗帘、灯具；
4. 最多 3 轮修复 [J-VER-02]；仍不通过的项写进"未解决清单"，说明是"放不下"还是"取舍没定"；
5. 只改本次涉及的对象 [J-VER-01]。

**第 9 步 · 常见错误与对策**

| 现象           | 原因                 | 对策                                  |
| -------------- | -------------------- | ------------------------------------- |
| 一进门就被看见 | 坐席正对门洞         | 坐席侧对门，把门移到余光里            |
| 逆光看不清对面 | 背窗坐               | 窗挪到侧前方，或把茶台转 90°          |
| 椅子拉不开     | 台边到墙不足         | 台靠一侧，整条通道留出来              |
| 水吧没地方     | 五件硬塞进小房间     | 砍水吧，或改成壁挂小托板              |
| 看着乱         | 出现两个以上视觉焦点 | 只留一个焦点，其余退到背景 [J-STY-03] |

## 依赖什么

| 工具                                      | 用途                                 | 状态    |
| ----------------------------------------- | ------------------------------------ | ------- |
| `catalog.search`                          | 取茶台/椅/柜/边几的 key 与默认尺寸   | 可 mock |
| `scene.read`                              | 读墙、洞口、房间净尺寸、门的开启方向 | 待成员1 |
| `candidate.propose + candidate.preflight` | 提交增删改，带版本与幂等             | 待成员1 |
| `candidate.preflight / candidate.review`  | 通行、门口连通、重叠、挂墙           | 可 mock |

与原项目 Skill 的差异：原流程把"茶室朝向"当纯审美描述，无法复核；本技能把"不对门、不背窗"落成可检查的位置关系（门洞与窗洞的相对方位），并明确"坐席背后靠实墙"这类只能人工看的项。

未适配时的降级路径（状态仍为 `pending_adaptation`）：

- 没有 `scene.*`：给出坐标方案（mm，`at` 为家具中心）+ 朝向说明（门在哪、窗在哪、人朝哪），交主控转场景；
- 没有 `candidate.preflight / candidate.review`：人工核算通道净宽与门口连通，并在交付里注明"未经工具检查"。

## 怎么验证

- **正向** `TEA-dev-01`：2.6 × 3.2m 茶室（内净约 7.2㎡，`min_passage` 取 700）。茶台 1200 × 650 偏东、两椅南北对坐、茶器柜贴东墙、水吧边几靠东南角、南墙开门。期望 `candidate.preflight / candidate.review` 全通过，且西侧留出贯通的 700 通道。
- **边界** `TEA-dev-02`：4.8㎡ 小茶室里"茶台 1500 × 900 + 两椅 + 茶器柜 + 水吧"五件全要，水吧挤在椅子后面。期望报 `OVER-01`（水吧与椅子投影重叠），技能应改为砍件（砍水吧或把台子缩到 1200 × 650）。

两个案例在 `examples/` 下，`ops.json` 可被 mock 引擎复跑；L1 结构与 L2 几何结果记录在 `manifest.validation`。
