# UTL-dev-02 · 把高柜挪到门后（边界／失败）

## 输入

同一个 1800 × 2600 家政间，南墙平开门 800（距西端 900 → 1700），洗烘并排在北墙。

## 用户／错误做法

"门后面那块地一直空着，柜子挪过去刚好，门开着的时候也能拿东西。"

## 技能应如何拒绝

1. **柜子压在门扇弧上**：门扇 800 × 800 扫掠区内不能有落地家具 [J-DOOR-02]，
   柜子占住这块地，门最多开到 90° 的一半，人进出要侧身；
2. **门后不是储物空间**：门后只能挂薄挂具（总厚 ≤80），任何 ≥300 深的柜/筐都会与门扇打架；
3. **连带失掉两条**：柜子挪走后，东墙那排 1200 长的柜子没了，囤货回到地面 → 通道被吃；
   而且扫地机基站与拖把池之间原本的空档会被打乱（本案例只演示门弧这一条可自动检查的错）。
4. 替代方案（按优先序）：
   - 高柜回东墙（现状 UTL-dev-01），南端留 1200 的开放端头；
   - 若东墙被管线占了，把高柜缩短到 600 宽、放在洗烘对面（西墙北段），但要让出洗烘前 700；
   - 门后只保留挂钩与拖鞋架（厚 ≤80），不放柜。

顺带说清"门后空着可惜"为什么是错觉：这间房只有 4.7㎡，门扇扫过去的那 0.64㎡ 是**门的运动空间**，
不是可用面积；把它当储物区，等于用"每次进门都要挪东西"换 0.64㎡。

## 判定

`check.run` 应 `pass = false`：报 `DOOR-02`（南门 800 × 800 扫掠区内有 `o_cab`）。
门口 300 深的落脚格仍在（柜子南沿 y=2300，门口带从 2300 起），所以**不应**报 `CIR-02`——
这一点用来证明引擎拦的是"门扇扫掠"而不是"门口被堵"，两条不是一回事。
