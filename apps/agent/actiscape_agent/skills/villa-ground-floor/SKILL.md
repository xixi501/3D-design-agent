# 独栋别墅首层

> v1 接入说明：本 Skill 只声明语义 capability，不能直接写正式场景、提交项目或执行任意脚本。所有修改必须形成候选，并由固定代码预检、渲染、审核和提交。

## 什么时候用

✅ 适用：

- 独栋/联排首层，面积 60–150㎡，含入户、客厅、餐厨、楼梯、可能有庭院；
- 用户要"进门有个玄关、别一眼看到沙发""厨房要能从车库/侧门直接进""客厅要能看到院子"；
- 需要定楼梯与电梯位置、家政/设备间位置、玄关柜长度。

❌ 不适用（转其他技能）：

- 多层全屋动线与挑空通高要一起定：本技能只做首层，二层交回主控或对应空间技能；
- 需要改承重墙、加建、改楼梯结构：超出本技能 [J-STA-03]；
- 只是单个客厅/餐厅布置：转 `living-dining-open`。

开工前必须问清五件事（问不到按保守值）：

1. 常住几口人、是否有老人（决定楼梯/电梯与首层卧室）；
2. 车库/侧门在哪一侧（决定服务动线入口）；
3. 庭院在哪个朝向、主要在哪活动（决定客厅/餐厨谁朝院子）；
4. 要不要电梯（预留井道 1600×1600 起）；
5. 家政间要放什么（洗衣、烘干、热水、配电、储物）。

## 怎么做

**第 1 步 · 先画两条动线，再摆家具**

- **公共动线**：入户 → 玄关（换鞋/挂衣）→ 客厅 → 餐厨 → 庭院门，全程不穿家政间、不穿厨房操作区；
- **服务动线**：侧门/车库 → 家政设备间 → 厨房，最好不经过客厅；
- 两条动线可以共用一个入户节点，但**不要共用一段走廊**：服务动线穿客厅是首层最常见的失败。
- 主通道 ≥900 [J-CIR-01]；从每扇门都能走到主要区域 [J-CIR-02]。

**第 2 步 · 玄关：先算收纳量，再定柜长**

- 鞋柜长 ≈ 常住人数 × 350mm + 访客 2 人 × 350mm；深 350；
- 挂衣 ≥500（落地挂衣架）+ 600 墙面挂件（钥匙盘/包/镜子）；有小孩时再加一排 800 高的矮挂钩；换鞋凳前 ≥600；
- 入户门扇开启后净宽 ≥900，鞋柜不得进门的开启区 [J-ENT-01]；门被鞋柜挡住是本技能要拦的第一类错误 [J-DOOR-02]；
- 玄关地面做 20mm 下沉或挡水条，把室外泥水留在玄关。

**第 3 步 · 楼梯与电梯：靠边、不占采光面**

- 楼梯贴外墙或靠服务核，**不放在客厅主视野与庭院视线通廊上**；
- 楼梯下净高 ≥2200 才可做储藏/卫生间，否则只做开放格；
- 电梯与楼梯相邻布置（共用井道墙）；轿厢 900×1200 起（本例 `elevator` 910×1160 是轿厢），井道再留 300 安装与检修，门宽 ≥800；
- 首层若有老人房，楼梯/电梯到老人房的门厅净宽 ≥900；
- 楼梯、电梯井属于结构，位置一旦确定不要为家具让路 [J-STA-03]。

**第 4 步 · 挑空与净高**

- 挑空只放在客厅（或客厅 + 楼梯间），不要在每个房间都做；
- 主要房间净高 ≥2400，梁下/局部吊顶 ≥2200 [J-STA-02]；挑空区灯具要能从二层检修；
- 挑空边缘做 1100 高栏杆，栏杆下不做可攀爬的矮柜。

**第 5 步 · 家政/设备间**

- 面积 ≥1.5㎡，能转身（门前 ≥700）；放洗衣机、烘干、热水、配电、清洁工具；
- 靠外墙或车库，便于排气排水；不贴卧室、不贴客厅沙发墙；
- 与厨房之间开门（服务动线最短），门宽 ≥800；
- 设备间门做百叶或留回风，不要完全密封。

**第 6 步 · 庭院与室内视线**

- 主要活动面（沙发、餐桌）朝庭院；庭院推拉门 ≥1800，门内外 400 内不放家具；
- 从入户到庭院有一条**不被高柜切断的视线通廊**：客厅与餐厨之间用家具分组，不用通高柜；
- 庭院侧窗/门内侧 150 不放 h>600 的落地家具（窗帘带），窗前 400 不放高柜；
- 庭院铺装与室内地面高差 ≤20，做排水坡而不是门槛。

**第 7 步 · 灯光与提交检查**

1. 灯光分三层：环境（筒灯/洗墙）、任务（餐台/操作台）、重点（挑空吊灯/庭院洗树）[J-LIGHT-01]；
2. 先提交楼梯、电梯、玄关柜（决定动线），`candidate.propose + candidate.preflight` 带 `base_version`；
3. `candidate.preflight / candidate.review` 看通道、门扇、推拉门 400、窗前柜；
4. 再提交客厅、餐厨、庭院侧家具；最多 3 轮修复 [J-VER-02]；
5. 只改本次涉及的对象 [J-VER-01]。

## 依赖什么

| 工具                                      | 用途                                         | 状态    |
| ----------------------------------------- | -------------------------------------------- | ------- |
| `catalog.search`                          | 取楼梯/电梯/玄关柜/沙发/餐桌/岛台 key 与尺寸 | 可 mock |
| `scene.read`                              | 读墙、洞口、房间、已有对象                   | 待成员1 |
| `candidate.propose + candidate.preflight` | 分批提交，带版本与幂等                       | 待成员1 |
| `candidate.preflight / candidate.review`  | 通道、门扇、推拉门、窗前柜、重叠             | 可 mock |

与原项目的差异：原流程按"一个房间"处理，本技能把"两条动线 + 服务核 + 庭院视线"作为首层的三个前置决策，房间内部的家具排布反而次要。
未适配时的降级路径（状态仍为 `pending_adaptation`）：

- 没有 `scene.*`：输出分区图（动线、服务核、庭院视线三条线）+ 玄关柜长度计算；
- 没有 `candidate.preflight / candidate.review`：按 900 通道、门扇 900、推拉门 400、窗前 400 四条人工核算，并注明"未经工具检查"。

## 怎么验证

- **正向** `VIL-dev-01`：8.0×12.0m 首层（轴线 96㎡）。南入户门 1000、北庭院推拉门 1800 + 窗 2600、西墙窗 3000；`stairRun` 靠东墙、`elevator` 在楼梯南侧、家政柜与洗衣机组服务核、玄关柜 1200 + 换鞋凳 900、客厅沙发朝北看院子。`min_passage` 设 900。期望 `candidate.preflight / candidate.review` 全通过。
- **边界** `VIL-dev-02`：把鞋柜放在门后 450（正落在门扇扫掠里）。期望报 `DOOR-02`（门扇开启区有家具）。技能应把鞋柜移到门侧实墙，保入户 900 净宽。

两个案例在 `examples/` 下；L1/L2 结果回填 `manifest.validation`。
