# 九类矩形空间文字生成验收（2026-11-12）

结论：本轮执行 Agent 自测在提交 **`a6f66c5fa65f3b3a064d1c148849989eed6039b0`** 上完成九类空间、每类两次共 **18/18** 真实生成。每次均由 DeepSeek 官方 `deepseek-flash`、真实 Node 持久层、两张 WebGL 候选检查图和独立视觉审核完成；正式项目均只增加一次修订，撤销恢复完整空白场景，重做恢复完整生成场景。主 Agent 的独立复跑尚未进行，本报告不代替最终验收。

本阶段支持从空白项目生成单个矩形空间并自动保存：客餐厅、阅读会客间、主卧、次卧、书房、厨房、卫生间、玄关、过道。不包含多房间文字生成、不规则房间、户型识别、照片生成或云部署；厨卫结果只作为场景布局，不宣称施工设计能力。

## 判据与独立核对

验收脚本不采信任务返回的“通过”，逐次独立读取正式项目和候选：

- 实际 4 面墙、4 个节点、1 个封闭矩形，房间净面积与净宽/净深；
- 门窗墙面、起点、宽度、离地和顶高；
- 每件家具的目录 key、类型、数量、目录 w/d/h、90° 朝向、越界、两两占地/高度重叠；
- 现有 `checkScene` 判据的阻断错误（门洞 800 mm、柜前 450–600 mm、门扇扫掠、墙体和窗区等）；
- 座椅朝向对应餐桌/书桌/茶几、床头柜位于床侧、柜门包络在房间内、过道中段保持 700 mm 可通行；
- 两张检查图 SHA 与同一候选哈希绑定、视觉审核来源为 agent、证据哈希一致；
- 初始候选检查与视觉审核通过后才提交；正式项目 revision 只增加一次；
- 重复任务请求、重复提交、撤销/重做不产生第二次正式修改。

判据版本绑定当前仓库文件。脚本记录 `packages/scene-core/src/index.ts`、`candidate.ts`、`rectangular.ts`、`actions.ts` 的 SHA-256；独立验收必须使用同一代码提交。完整哈希见[版本化证据](evidence/generation-acceptance-20261112.json)。

## 失败记录与修复依据

- **初始化授权缺口**：在基准 `cb5b800` 上，生成流程先登记编辑授权，初始化候选未携带授权引用，提交端以 `AUTHORIZATION_CONFLICT` 拒绝。先在真实 Node 持久层复现，再引入 `kind:"initialize"` 授权并补齐创建、检查、审核、提交校验。
- **开发矩阵 9 类首轮**：`dev-all1` 中次卧因模型结构化输出失败触发兜底、兜底候选数量不符后耗尽预算。保留原任务和候选；随后缩小生成设计角色的工具调用、约束视觉审核只做代码未覆盖的判断，`dev-all2` 达到 9/9。
- **最终矩阵前的朝向误判**：独立验收脚本把餐椅本地方向当作通用方向，误报首轮布局；实际图像与代码检查正常。修正脚本后，产品侧增加“初始化座椅朝向”门禁，用代码阻挡相反朝向，避免只靠视觉审核漏判。
- **浏览器首轮失败**：新建项目回廊选择器和精确编辑目标选择在测试脚本中不稳定，均为测试脚本问题，不是运行代码绕过检查；保留失败截图，修复脚本后通过。
- **卫生间兜底与修复**：模型两次结构化输出失败后，旧兜底模板携带的旧尺寸被正确拒绝并导致预算耗尽；随后移除模板尺寸、增加代码托底卫生间布局，并从逐字 evidence 恢复被模型漏掉的净深。最终两次卫生间的兜底候选均通过相同检查与视觉审核，保留每轮候选图、任务轨迹和检查报告。
- **澄清补充空白字符**：用户补充以换行拼接，理解模型把同一原文写成空格。授权改为只归一化空白、仍要求逐字子串；编造或改写仍拒绝。阶段 1 澄清案例随后 16/16。

## 已知限制

- 仅支持单个矩形空间；不做多房间文字生成、不规则轮廓、户型识别、照片生成或云部署。
- 家具尺寸使用目录默认值，不支持生成时通过缩尺绕开空间不足；空间不足会停止并保留候选与问题。
- 视觉审核仍可能对朝向/功能关系给出与代码判据不一致的意见；代码检查是阻断门，视觉审核补充明显布局问题。发现不一致时保留失败证据并修正提示或判据，不通过降低阈值放行。
- GLB 仍按矩形占地检查，不做精确网格碰撞；未覆盖完整无障碍、照明或法规设计。
