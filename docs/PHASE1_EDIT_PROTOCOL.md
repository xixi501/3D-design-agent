# 阶段 1 编辑协议

已有场景编辑保持单用户、单实例、SQLite/LangGraph。`workflow.py` 只编排；`exact_edits.py` 负责完整解析和精确运算，`edit_execution.py` 负责授权与候选，`edit_results.py` 统一正常提交和恢复结果。

## 授权生命周期

在设计或预检候选之前，Python 主控调用 `POST /api/projects/:id/edit-authorizations`，提交 `taskId`、`version`、`baseRevision`、`requestText`、只读 `referenceIds`、`scope` 和可选 `operations`。登记接口属于内部主控协议，不暴露给模型工具。

授权覆盖对象、字段、删除清单、每次新增额度、资产候选池和局部区域。精确操作必须提供原文片段；服务端从基准场景独立计算预期字段值，检查候选并在提交前重新核对。参考对象不进入修改目标。

活动组元数据也需要独立授权：仅在用户明确要求创建/组成家具组时登记 `allowActivityGroups`。提到“阅读角”不会自动允许保存分组。布局候选不能附带未授权的 source 元数据。

候选携带 `authorizationVersion` 和 `authorizationScopeHash`。创建、检查、审核、提交都核对授权；同版本不可改写。修复复用原授权，不增加对象、字段、数量或目录权限。用户补充需求先调用 `POST /api/projects/:id/edit-authorizations/invalidate` 推进需求版本，再重新理解；旧候选保留内容与哈希，但不能提交。

手工修改造成 revision 冲突最多重新规划一次。保留原对象与范围，重新计算相对数值；目标消失或待写绝对字段/设计字段已被手工修改时停止，提示冲突，避免覆盖修改。

旧候选不改写原内容或哈希，继续走原有冻结协议。已经升级为独立授权的任务不能通过省略引用回退旧协议。提交以原 operationId 去重，已提交结果可以重放。

## 执行和检查

完整精确意图只包含目标、update/delete、绝对 values/相对 deltas 和 source_quote。组合操作滚动计算，合并为一份事务；不能完整解析时交给理解角色，不能先执行一部分。纯否定和已满足请求返回 `noChange=true`，不创建候选或 revision。

服务端根据独立授权和实际编辑类型决定检查策略。精确编辑为代码运算、逐字段验证和完整场景几何检查；无需设计角色、截图或视觉审核。模型理解的精确请求也转为同一代码路径。新增/局部布局必须渲染并视觉审核，客户端 verification 仅为兼容输入，不能作为豁免依据。

`result.verification` 记录实际模式、是否渲染和视觉审核。`result.metrics` 记录模型调用、输出图像数量、修复次数、阶段耗时及活动耗时；等待用户输入与停机时间不计入活动预算。图像数量按俯视图和斜视图分别计数。

## 取消和恢复

提交前取消阻止后续提交。原子提交开始后收到取消请求，继续核对原候选实际结果；已保存时显示已保存及取消到达过晚。提交响应丢失或服务重启都沿用候选和 operationId，统一生成摘要、焦点和结果。

`waiting_input`、`reason=check_failed`、`conflict`、`cancelled`、`failed` 分别表示需要澄清、检查不通过、版本冲突、取消及执行失败。界面刷新重连读取持久任务；失败或冲突可在原任务继续，补充需求会产生新授权版本。

门、柜、电器以手动交互为主，保留现有对话入口，不扩展该能力作为本阶段目标。户型、照片、整屋设计和部署均保留现有实验入口。
