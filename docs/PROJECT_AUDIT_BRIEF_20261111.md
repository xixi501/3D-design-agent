## 1. 我们在做什么

“演境 / ActiScape”是一个 AI 3D 空间设计工作台：

- 2D 平面、分屏、3D 查看与漫游；
- 家具目录、墙体门窗、房间与尺寸编辑；
- 确定性场景检查（碰撞、净空、门洞、台面等）；
- AI 对话生成/修改空间，走 Candidate → CheckScene → Commit；
- 目标方向是多 Agent 协作，而不是单纯聊天套壳。

核心原则：**几何和提交由确定性引擎保证，Agent 负责理解意图和生成候选。**

## 2. 当前架构

- `packages/scene-core`：场景模型、命令、几何检查、Candidate；
- `apps/editor`：工作台前端，直接编辑与 Agent 侧栏；
- `apps/service`：项目存储、命令、检查、SSE、资产；
- `apps/agent`：PolicyController、LangGraph Workflow、角色和 Skill；
- `deploy/agentarts-minimal`：AgentArts 运行时原型。

两条主要链路：

1. **直接编辑**：前端命令 → service 提交 → 检查；
2. **Agent**：对话任务 → Policy → Workflow → Candidate → 检查 → 提交。

## 3. 目前确实可用的部分

- 确定性编辑、撤销/重做、保存、SSE 同步；
- 3D 开关门/柜门/电器，漫游 HUD、E 标记、俯视导航；
- 场景检查与问题列表；
- PNG/PDF/JSON 导出；
- 文本生成矩形房间、局部家具编辑、部分小范围修复；
- 户型图/照片/动作/技能路由等受控流程；
- Node 82、Python 187 已通过；最近一次 `npm run test:all` 在按房间修复改动前通过，之后只做了 Node、build 和浏览器手动验收。

这些不等于“任意全屋都可用”。

## 4. 明确未完成或不可承诺

- **全屋布局质量**：仓库中的 B（2BHK 冻结样例）有 30+ 项检查问题，是坏样例，不是可靠产品演示；
- **全屋一键修复**：结构问题（门宽不足、卫生间净尺寸不足）无法靠移动家具解决；
- **真实户型图 VLM**：`visionAvailable=false`，真实上传能力未闭环；
- **真实照片转 3D**：接口存在，但真实 V100 / `apps/asset-service` 未接入；
- **真实华为云 AgentArts**：仅本地模拟和运行时验证，未做真实云部署；
- **语义设计质量**：缺少动线、家具关系、风格一致性、全屋功能完整性的系统评估；
- **候选对比、分享、多选对齐**等产品能力仍缺。

## 5. 当前最高风险

1. **样例质量风险**：坏样例仍可能被当成产品能力展示；尚未建立“样例必须 0 error”的 CI。
2. **能力表述风险**：确定性编辑器稳定，但 Agent 能力仍偏受控场景；容易被误解为“全屋 AI 已可用”。
3. **修复分类风险**：检查问题没有区分家具可修、结构无解、数据错误、规则冲突；错误问题会被送进家具 Agent。
4. **检查目标污染**：`CIR-02` 等检查项可能把大量无关家具放进 `objectIds`，导致 Agent target 不精确。
5. **外部依赖风险**：真实 VLM、照片资产、华为云均未完成，不能按生产可用验收。
6. **测试盲区**：测试通过不等于用户可完成真实任务；B 的问题说明测试没有覆盖样例质量与结构冲突。

## 6. 建议审核重点

请独立检查：

- 作为普通用户，从打开项目到完成一次编辑/漫游/修复，是否真的顺畅；
- “已完成”的能力是否有真实浏览器证据，而不是只看文档；
- B 等样例是否应该继续展示；
- 检查问题分类和 Agent 修复边界是否合理；
- 文档、UI 文案与实际能力是否一致；
- 测试是否只覆盖 happy path。
