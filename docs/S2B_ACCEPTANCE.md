## 生成案例、失败记录与真实 Skill

正式案例固定为：

1. **6000×4000 mm 客餐厅**：南墙入口距西侧内墙 400 mm，北墙窗居中；三人沙发、茶几、电视柜、餐桌各一，餐椅四把、落地灯一盏。输入使用米。
2. **5000×3600 mm 阅读会客间**：南墙入口距西侧内墙 3500 mm，东墙窗居中；单人沙发两把、茶几、书柜、落地灯各一。矩阵输入使用厘米。

数据检查包括真实净尺寸、4 面墙、1 个封闭房间、2 个开口、逐类型数量、目录默认尺寸、候选与正式快照相等、重复提交不增加版本、一次撤销回空白及重做恢复。每次成功均有四角色和真实 search_catalogue_batch / precheck_initialization / candidate_checks 调用记录，以及两张固定候选图。

**首次正式批次为 2/4，通过与失败全部保留。** 两次失败中，资产角色把“每项需求选一个配方”误解为“每件家具返回一个选择”，例如把四把餐椅展开为四条，导致请求索引和数量不一致。系统在正式写入前拒绝，两份项目保持空白、修订号 0。见 [修复前总表](evidence/s2b/generation/pre-fix/report.json)。

修复为：向角色提供明确零基请求索引，用动态 Pydantic 校验精确长度、索引和真实目录 key，错误由 LangChain 结构化工具反馈纠正，所有模型重试继续计入预算。修复后重新执行完整批次，4/4 通过。设计角色内部仍会预检或校正布局，外层修复数为 0 不表示跳过预检。两个更早的开发冒烟结果另存于 development-smokes，不充当正式矩阵。

实际加载 Skill：`rectangular-living-reading @ 0.1.0`，内容哈希 `ff35c055a715485ef9b93fef6e0b656ae61b79abafd6b4da75ff45a673399a50`。它有来源、MIT 许可、适用条件和所需工具，正文实际进入设计与检查角色上下文；任务保存内容快照，恢复不重新选择版本。该交付是首个可验证样例，不代表正式 Skill 池或 GEPA 已完成。

## 边界与后续

- 只生成空白项目中的单个矩形客餐厅或阅读会客间；不能覆盖已有项目。关键尺寸和门窗不推测，默认值明确显示。
- 生成以目录默认家具尺寸为基础；生成后继续使用现有尺寸、颜色和摆放编辑。定制柜、厨房和自由造型配方的手工能力保留，对话配方编辑仍后置。
- 800 mm 是局部门前布局规则；GLB 仍用矩形占地。不声称提供完整通路、支撑面、精确网格或规范验证。
- 数据库增量升级为 Node 版本 2 / Agent 版本 1，项目 JSON 格式仍为 1。旧请求、候选哈希、历史和会话兼容。升级前完整停服备份已保留，回退须使用对应代码及备份。
- 完整 S2 下一步为两个清晰户型图案例与集成复验。照片服务、正式 Skill 池/GEPA 和 AgentArts 完整云端部署仍分别属于后续阶段；本轮没有完成云端部署。

使用与恢复见 [S2B_RUNBOOK.md](S2B_RUNBOOK.md)，接口见 [AGENT_API.md](AGENT_API.md) 及两个 OpenAPI 快照。
