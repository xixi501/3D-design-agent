# 成员二阶段计划：本地可视初版 + 学校 GPU 服务器真实生成

> 本文保存阶段开始时的实施计划。实际完成状态、真实案例和当前限制以 [成员二进度](member2-progress.md) 为准。

## 背景与目标

实现成员二分工：提交单件物品照片，获得处理状态与可复用的带材质 GLB，在独立网页查看器中检查效果，并向成员一、三提供清晰接口和进度记录。

以 `dev/assets` 为工作分支。本机为 Apple M3/Metal，无 CUDA；真实生成使用学校 NVIDIA GPU 服务器，通过网页控制面板上传代码包并由成员二在服务器终端执行。密码、私钥或令牌不进入文档和版本库。

## 实施方案

提供两种明确区分的后端：

- `demo`：使用团队已有示例 GLB，在本机跑通上传、任务状态、资产持久化和三维网页预览，只用于流程演示，不声称是照片真实生成。
- `hunyuan`：封装 Hunyuan3D 官方图像到几何、去光照、几何贴图与 GLB 导出流程。模型在进程内复用，真实生成在 NVIDIA GPU 服务器执行。

交付可上传到网页控制面板的 ZIP 和逐步操作说明。先检查 GPU、CUDA、Python、显存与磁盘，再确定匹配的依赖。真实生成以服务器实际产物和网页外观检查为准，本机演示成功不替代真实验收。

## 主要改动

### 1. 仓库与接口对齐

- clone 仓库并设置 `origin`，使用 `dev/assets`。
- 检查分支、提交记录和协作约定，不覆盖其他成员工作。
- 对齐成员一的 GLB 入场、坐标与尺寸约定，以及成员三的部署要求。

### 2. 独立资产服务与网页

- 图片提交、JPEG/PNG/WebP 校验、任务 ID、状态查询、结果获取和持久化目录。
- 状态覆盖排队、处理中、完成、失败，失败包含可读原因。
- 保存输入、GLB、元数据和任务记录；重启后仍能读取已完成资产。
- 支持幂等键，重复提交返回同一任务，不同内容使用相同键时返回冲突。
- 元数据包含资产 ID、相对模型 URL、生成模式、模型版本、耗时、单位、Y-up、原点、包围尺寸和尺度校准状态。
- 独立网页支持图片选择、状态轮询、错误显示、GLB 下载、旋转缩放与元数据展示。

### 3. 学校服务器真实生成

- 固定 Hunyuan3D 官方代码版本，封装读图、去背景、几何、去光照、贴图和 GLB 导出。
- 懒加载并复用管线，捕获依赖、显存、权重和生成异常，不把失败标为成功。
- 提供依赖、权重、资源、启动参数与调用样例；地址和凭证通过环境变量配置。
- 固定花盆、花瓶、摆件案例，保存输入、产物、耗时和失败记录。

### 4. 上传包与服务器手册

- 生成不含本机绝对路径、缓存、任务数据、凭证和大型权重的 ZIP；ZIP 不提交到 Git。
- 手册覆盖上传、解压、环境检查、依赖安装、权重下载、启动、端口映射和浏览器验证。
- 提供服务日志、健康检查、停止/重启、结果下载和常见错误处理。
- 公网或共享平台必须保留 API Key，不开放无认证管理接口。

### 5. 进度与交接

- 说明本机 demo 和服务器真实生成的不同启动方式、API 字段、结果获取与限制。
- 进度文件分别记录本机验证、服务器真实生成、固定案例、当前问题和下一步。
- 明确单张照片的背面与遮挡属于模型补全，真实尺寸由主系统向用户确认。
- 阶段完成后提交并推送 `dev/assets`，通过分支与文档和其他成员同步；是否合入 `main` 由主系统负责人通过 PR 决定。

## 验证方式

- 本机 demo 实际完成图片提交、任务完成、GLB 加载、材质显示与旋转，而非仅检查接口。
- 验证无效图片、任务查询、GLB 下载、幂等提交、失败反馈和重启恢复。
- 检查 ZIP 在干净目录解压运行，不依赖本机路径。
- 服务器依次验证健康检查、真实生成、GLB 下载、SHA-256 和三维外观。
- 固定案例必须保存输入、结果、耗时与失败记录；文件能打开不等于外观通过。
- 交付前运行 `git diff --check`，清理缓存、日志和临时文件，不提交运行时产物。

## 当前边界

- 单进程、单工作线程用于首版，不作为分布式生产队列。
- 未完成任务重启后不自动续跑，已完成资产可恢复。
- 首版不推断真实尺寸，不负责房间落点、编辑、撤销与保存。
- 真实案例仍需检查背面材质、网格规模和网页加载性能；轻量化根据实测结果进行。
