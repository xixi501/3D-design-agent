## 3 技能池是怎么来的

**第一步：解剖上游，抽判据而不是抄流程。**
上游 `house-plan-designer@b94183f9` 只有一个总 Skill，形态是"读图 → 写 HouseSpec → 跑 `build.py`/`check.mjs`/`qa.mjs` → 交付 HTML"。它复用的是**判断**（通道 700、窗帘 150、推拉门 400、高柜挡窗 400、挂墙必实墙、门扇开启、家具 key 与朝向、面积下限），不是**脚本**。于是把它拆成判据库：`J-CIR/DOOR/CUR/WIN/WALL/OVER/PROP/STA` 这些 ID 全部来自上游文本，保留 MIT 来源标注。

**第二步：补外部。**
找到并读完一个同类开源技能 [interior-design-expert](https://github.com/curiositech/some_claude_skills/tree/main/.claude/skills/interior-design-expert)（anthropometric 通行值 900/600/450、家具净距、IES 照度与色温、Munsell 配色）。只取**可核对的数值与结构**，写进判据库的 `J-CIR-*`、`J-LIGHT-*`、`J-COL-*`，不复制其文本。

**第三步：自写。**
上游没有的技能自己写：会客/阅读分组、适老、宠物、出租房、开间、别墅首层、办公工位、风格统一、光色、检查修复、户型进场、照片物品导入。写的过程中发现判据库缺 13 条（窗墙净距、屏幕眩光、灯位对中、视频取景、安全固定、可逆改造、端头绕行、会议长桌净空、厨房选形、检修可达、机位排水、五金一致性、未解决清单完整性），补进 v0.2——**这些是写技能"写出来"的缺口，不是拍脑袋加的**。两批各提了一个 `J-LIGHT-05`、一个 `J-CIR-09`，按先到先得合并，后来的改为 `J-LIGHT-06` / `J-CIR-10`。

| L3 真工具 | 接成员1 的 `scene.*`/`check.run`、成员2 的 `assets.*` | 未接真工具，故全部 `pending_adaptation`；**契约级已用替身跑通**（44 案例走 HTTP 47/47，见 [capability_without_m1m2.md](capability_without_m1m2.md)） |

L2 的判定不是"跑完没崩"，而是**双向断言**：

- 正向案例：`pass = true`，且 `must_not_trigger` 里的码一个都不许出现；
- 边界案例：`pass = false`，且 `must_trigger` 里的码必须出现。
  这证明"技能警告的错误，检查器真的抓得到"——技能与检查口径一致，而不是各说各话。

边界案例覆盖到的拦截码：`CIR-02`（门口被堵 / 可达通行区不足 / 无 700 通道）、`DOOR-02`（门扇扫掠被占）、`DOOR-01`（推拉门前 400）、`CUR-01`（窗帘活动区）、`WIN-01`（高柜挡窗）、`OVER-01`（家具重叠）、`ASSET-02`（台面物超出支撑面）。每个码都有至少 2 个案例在真实几何上触发过。
