# 判据库 v0.2（Skill 池共用）

> v0.2（2026-11-07）：新增 J-CUR-02（窗墙前净距）、J-LIGHT-05（屏幕眩光）、J-LIGHT-06（灯位对中）、J-VIEW-01（视频取景）、J-SAFE-01/02（安全固定、可逆改造）、J-CIR-09（端头绕行）、J-CIR-10（会议长桌净空）、J-KIT-05（厨房选形）、J-ENT-03（检修可达）、J-BAL-02（机位排水）、J-STY-04（五金一致性）、J-VER-03（未解决清单完整性）。均由写技能时的实际缺口提出，见文末"变更记录"。编号冲突（两批各自提了 J-LIGHT-05 / J-CIR-09）按先到先得合并，后来的改为 J-LIGHT-06 / J-CIR-10。

所有技能**只能引用这里的判据 ID**，不再各自写一套阈值。判据变更走版本（见 `FORMAT.md` 的版本规则），技能引用 ID 即可自动获得更新。

**来源标注**：
- `上游` = house-plan-designer@b94183f9（`reference/furnishing.md`、`workflow-check.md`、`spec-format.md`）的既有规则，MIT；
- `外部` = [interior-design-expert](https://github.com/curiositech/some_claude_skills/tree/main/.claude/skills/interior-design-expert)（anthropometric / IES 数据）与 NKBA 通行经验；
- `规范` = 引自 GB 50096 常被引用的下限，**须按现行版本与地方标准复核**；
- `经验` = 行业通行做法，无强制力，用于"好看/好用"而非合规判断。

**可检查性**：`自动` = mock 引擎或检查工具能判定；`半自动` = 需要工具给数据（如面积、材质）再判；`人工` = 只能靠评审清单。

## 使用规则
1. 技能正文引用判据写 `[J-CIR-01]`；**不得**在技能里另写数值（避免双份真源）。
2. 判据冲突时取更严格者，并在技能里写明"以 X 为准，因为 Y"。
3. `经验` 类判据可以按场景放宽，但必须在技能里显式声明放宽理由；`上游/规范` 类不放宽。
4. 新增判据 → 升 `JUDGEMENTS.md` 次版本号 → 技能引用后重新跑 lint 与 dry-run。
