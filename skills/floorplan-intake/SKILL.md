# 户型图/需求进场：先补齐，再布置

## 什么时候用

✅ 适用：
- 用户发来户型图（照片/截图/PDF 转图）或只给文字需求；
- 场景已生成但缺尺寸、缺房间名、门窗类型不清；
- 用户说"你看着办"——这时更需要把假设写出来。

❌ 不适用：
- 场景已确认、尺寸完整：直接进具体房间技能（客餐厅/主卧/厨房…）；
- 用户要的是拆改方案：结构改动不在首版范围 [J-STA-03]；
- 多楼层/别墅整栋：走别墅技能，本技能只做单层确认。

## 怎么做

识图与尺寸识别由主系统执行，本 Skill 只组织输入与确认项。

**第 1 步 · 记录来源与可信度**
用户给的是哪种输入、清晰度如何、有没有尺寸标注；把"来源"写进交付（图纸 / 口述 / 已有场景）。同一份信息有多个来源（原图 + 布置图）时，明确"结构按哪张、家具按哪张"。

**第 2 步 · 要素清单（逐项打勾，缺的进第 3 步）**
- 总尺寸与分段尺寸（没有分段就只有总尺寸，比例只能估）；
- 每个房间的名字与位置、面积（与图上标注对照）；
- 门：位置、宽度、开向、门轴在哪端（套卫的门常开在卧室里）；
- 窗：类型（平开/推拉/落地/高窗/飘窗）、窗台高、洞口宽；
- 承重墙、柱、烟道、管井、下水口；电箱位置；
- 指北针方向（决定采光判断）。

**第 3 步 · 缺失清单与假设（不要静默补齐）**
每缺一项，写一条"假设 + 影响"：
- 层高未知 → 按 2800 假设，标注"按常规估" [J-STA-02]；
- 窗台高未知 → 按 900 假设（落地窗按 0）；
- 面积与标注差 > 5% → 回查墙体是否漏段；
- 尺寸链自相矛盾（同一处两个标注差 > 30mm）→ 两条都记下，选一条并说明依据。
假设写进"待确认清单"（≤7 条，按影响排序）：用户在 30 秒内能看完，才愿意回答。

**第 4 步 · 交叉核对（三条硬检查）**
1. 房间面积是否满足下限 [J-STA-01]：低于下限的房间，布置前就要提示"这个房间放不下标准家具"，而不是等布置失败；
2. 门窗是否被墙吞掉/悬空（漏墙、错位）；
3. 主要通道是否在图纸上就断了（门对门、门对柜），提前标出来。

**第 5 步 · 输出两件东西**
- **待确认清单**：只问真正影响方案的（层高、窗台高、承重、房间用途、常住人口）；
- **假设表**：字段 = 项 / 假设值 / 依据 / 影响面；交付时逐条列出，用户改哪条就重算哪条。

**第 6 步 · 交给布置技能**
确认后（或用户明确"按你的假设先做"），才进入具体房间技能。布置阶段只改室内对象，不动墙体门窗 [J-VER-01]。

## 依赖什么

本技能只使用以下语义能力（不含任何写场景权限）：

| capability | 用途 |
|---|---|
| `scene.read` | 读取当前场景/现状 |
| `candidate.preflight` | 几何与净空预检，返回问题码 |

**边界**：识图与尺寸识别由主系统执行；本 Skill 只组织输入、假设与确认项，不产出候选、不渲染。
**降级路径**：输出要素表、假设表与待确认清单，交主系统生成场景。

## 怎么验证

- **正向** `FIN-dev-01`：3.0 × 3.8m 主卧（11.4㎡），1.5m 床 + 1.0m 衣柜 + 一个床头柜，通道满足 700。期望 `candidate.preflight` 通过。
- **边界** `FIN-dev-02`：同样 3.0 × 3.4m（10.2㎡）的房间，用户坚持 1.8m 床 + 2.0m 衣柜。期望报 `CIR-02`（无 ≥700 通行区）——技能应在进场阶段就提示"这个组合放不下"，而不是硬塞后说"已尽力"。
