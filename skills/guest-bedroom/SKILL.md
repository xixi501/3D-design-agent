# 次卧 / 客房布置

## 什么时候用

✅ 适用：
- 次卧、客房、保姆房、客房兼书房，使用面积约 6–14㎡，已有含墙体与门窗的场景；
- 用户给了面积或户型图，要一版能落地（能买、能摆、能走人）的初稿；
- 用户说"平时没人住，父母/朋友来要能睡"，或"这间要当书房，偶尔睡人"。

❌ 不适用（转其他技能）：
- 主卧：转 `master-bedroom`（梳妆、双人床两侧对称、衣柜容量是另一套判断）；
- 儿童房：转 `kids-room`（成长性与安全优先）；
- 要先补尺寸再谈布局：先走 `floorplan-intake`；
- 要拆墙、加窗、改门洞：超出本技能，交回主控并说明原因。

开工前问三件事（问不到就按保守值）：
1. 谁住、一年里住多久——决定第 1 步的用途判断；问不到按"临时住 + 收纳"做，因为靠墙摆法可以事后改成居中，反过来不行；
2. 床要 1.2 还是 1.5——1.5 双人床会吃掉一整面墙；问不到按 1.2 做，并留出换 1.5 的余地（床侧不贴死）；
3. 衣柜要多大、门往哪开（平开还是推拉）——决定了柜前要留多少；问不到按推拉门做，柜前压力小。

## 怎么做

**第 1 步 · 先定用途，再动家具（本技能的核心判断）**

| 用途 | 特征 | 布置重心 |
|---|---|---|
| 临时住 + 收纳 | 一年里多数时间空着，来客才睡 | 满墙收纳 + 一张能快速清空的床；书桌可折叠 |
| 长期住 | 有固定住的人，衣物与书都在房里 | 衣柜与书桌都要"日常可用"，通道不能靠挪家具让出来 |

用途不同，后面每一步的取舍顺序都不同：临时住优先"柜子多、床能收"；长期住优先"柜门能开、桌能坐、床两侧能下人"。

**第 2 步 · 量墙、定床头墙**
`scene.get_snapshot` 取墙与洞口，按"连续、无洞口"筛出可用墙段。床头选**最长的一段实墙，且避开窗**：床高通常高于 600，落在窗内侧 150 的窗帘活动区里就违反 [J-CUR-01]。窗前宁放矮几、矮柜，不放床头。

**第 3 步 · 床的两种摆法（第二个核心判断）**

| 摆法 | 适合 | 得到什么 | 代价 |
|---|---|---|---|
| 靠墙（长边贴墙） | 单人 / 临时住 / 房宽 < 2600 | 省出一整条通道，能放 600 深衣柜 | 换床单要爬上床；两人睡时里侧的人下不来 |
| 居中（两侧留通道） | 长期住 / 双人 | 两侧都能下人，床侧 ≥ 600 [J-CIR-04] | 房宽 < 2800 时放不下 1.5m 床 + 两侧 600 |

1.2m 单人床靠墙后，房宽 2600 仍能留出 900 以上通道 [J-CIR-01]；1.5m 床要居中，房净宽至少按"床宽 + 两侧床侧通道"反算，算不下就回退到靠墙或换 1.2m。

**第 4 步 · 衣柜与书桌的争夺（第三个核心判断）**
- 顺序：**先衣柜，后书桌**。衣柜是硬需求且体量大，书桌可以折叠、可以上墙、可以缩到 900 长；
- 柜门开启：平开门前 ≥ 750；推拉门 ≥ 500 [J-CIR-06]。柜门开不全，等于衣柜少一格；
- 床尾到柜面 ≥ 600 [J-CIR-01 的通行口径]，否则柜门只能开一半；
- 衣柜长度不超过所在墙面长的 2/3 [J-PROP-01]；超了就把柜拆成"衣柜 + 矮柜"两段。

**第 5 步 · 客房兼书房：折叠与隐藏**
- 折叠书桌（900–1200 长、翻板深 400–500）或壁挂桌板，写完收起，把通道还给床；
- 书桌常态位优先放在**窗侧墙**而不是窗前：桌前要有 900 使用区，窗前 150 又不能让高家具 [J-CUR-01]；
- 收纳下沉：床下抽屉、床尾矮柜代替第三个高柜；
- 隐藏床（墨菲床/沙发床）只在"一年来人不超过几次"时选，且必须核对展开后的通行——展开态的净空要按本技能的通道口径算一遍。

**第 6 步 · 窗与门的净空（客房最容易踩的两处）**
- 门扇扫掠区（门宽 × 门宽）内不放落地家具 [J-DOOR-02]；"门后那块空着"是最常见的错误，柜子一放门就开不到 90°；
- 门口 300 深内要留可落脚的自由格，不能被柜子切断 [J-CIR-02]；
- 窗帘盖满窗洞、两侧各多 100–200；窗内侧 150 内不放高于 600 的落地家具 [J-CUR-01]；
- 挂墙件（壁挂桌板、镜子、层板）必须落在实墙、避开洞口与窗帘盒。

**第 7 步 · 面积下限核对**
单人卧室与次卧按 5㎡ 下限核对，双人卧室按 9㎡ 核对 [J-STA-01]。低于下限时不要硬排，改报"这间更适合做储物间/书房"，把结论交给用户。

**第 8 步 · 提交与检查（不要一次改完再检查）**
1. 先提交"床 + 床头柜"，带 `base_version`、`op_id` 唯一；
2. `check.run` 看门扇、窗帘、重叠；
3. 再提交衣柜，检查柜门开启与床尾通道；最后提交书桌/折叠桌；
4. 最多 3 轮修复 [J-VER-02]；3 轮后仍不通过的项写进"未解决清单"，逐条给原因与替代方案；
5. 只改本次涉及的对象，户型与无关家具不动 [J-VER-01]。

**第 9 步 · 常见错误与对策（本技能最常被返工的六种）**

| 现象 | 原因 | 对策 |
|---|---|---|
| 门只能开一半 | 衣柜/书桌进了门扇扫掠区 | 门后只留挂钩、镜子等薄件，柜子挪到门洞另一侧 |
| 窗帘拉不动 | 床头或高柜贴了窗 | 床头换到实墙，窗前只放矮几、矮柜 |
| 床尾走不过人 | 床居中但净宽不够 | 改靠墙摆法，或把 1.5m 床换成 1.2m |
| 柜门开不全 | 平开门前 < 750、推拉门前 < 500 | 换推拉门，或把柜改浅、拆成两段 |
| 书桌坐不进去 | 桌前没有使用区 | 改折叠桌/壁挂桌板，写完收起 |
| 房间"看着满" | 三件大家具挤在同一面墙 | 把书桌挪到窗侧墙，柜留在最长实墙 |

## 依赖什么

| 工具 | 用途 | 状态 |
|---|---|---|
| `catalog.search` | 取床/衣柜/书桌/床头柜的 key 与默认尺寸 | 可 mock |
| `scene.get_snapshot` | 读墙、洞口、房间净尺寸、已有对象 | 待成员1 |
| `scene.apply_edits` | 提交增删改，带版本与幂等 | 待成员1 |
| `check.run` | 门扇、窗帘、重叠、通行、面积下限 | 可 mock |

与原项目 Skill 的差异：原流程把"次卧怎么摆"写在户型描述的注释里，无法复核；本技能把判断拆成"用途 → 摆法 → 争夺顺序"三步，每一步都能落到 `check.run` 的码上。

未适配时的降级路径（状态仍为 `pending_adaptation`）：
- 没有 `scene.*`：用文字给出坐标方案（mm，x 向右 y 向下，`at` 为家具中心）+ 一段平面描述，交主控转成场景；
- 没有 `check.run`：按第 3、4、6 步的判据人工核算，并在交付里注明"未经工具检查"。

## 怎么验证

- **正向** `GBR-dev-01`：3.0 × 3.6m 次卧（内净约 9.5㎡）。床头靠实墙避开窗、床侧留 700 以上通道、衣柜放南墙、书桌靠东墙、门扇区让开。期望 `check.run` 全通过。
- **边界** `GBR-dev-02`：把 1.0m 衣柜塞进门后"那块空着的地方"。期望报 `DOOR-02`（门扇开启区）与 `CIR-02`（门口被堵）；技能应拒绝该位置，改为衣柜放南墙、门后只留挂钩。

两个案例在 `examples/` 下，`ops.json` 可被 mock 引擎复跑；L1 结构与 L2 几何结果记录在 `manifest.validation`。
