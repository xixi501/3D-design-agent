# 一字 / L / U 形厨房布置

## 什么时候用

✅ 适用：
- 独立厨房或封闭式厨房，使用面积 3–10㎡，已有墙体与门窗；
- 要出初稿，或用户只改其中一段（"水槽挪到窗下""冰箱进不去"）；
- 已有旧厨房，想在不动水电的前提下重排柜体与家电。

❌ 不适用（转其他技能）：
- 餐厨一体、要中岛、要早餐吧台：转 `dining-island`（岛台间距与灯光逻辑不同）；
- 面积 < 3㎡ 或与起居合一：转 `studio-micro`；
- 要改燃气立管、排烟道、下水立管位置：超出本技能，交回主控并说明原因 [J-VER-01]；
- 要拆墙扩厨房：先走 `floorplan-intake` 补结构信息，本技能不判断承重。

开工前只问三件事（问不到就按保守值）：
1. 开间与进深是净尺寸还是轴线尺寸（差一面墙厚，足以让双排变成单排）；
2. 燃气表/灶位与下水立管在哪一侧（决定水槽与灶台的先后顺序，不可随意镜像）；
3. 冰箱宽深与开门方向（对开门要留两侧散热缝，单门只要一侧）。

## 怎么做

**第 1 步 · 先量开间，再定形（本技能的核心判断，顺序不能反）**

开间 = 两墙内皮净距。柜深按 600 计，通道按 [J-KIT-02]，于是：
- 单排：开间 ≥ 600 + 通道；
- 双排：开间 ≥ 2 × 600 + 双排通道；
- U 形：开间 ≥ 3 × 600 + 通道（短边还要能放下 600 的转角）。

由此得到选形表（阈值是从上面两条推出来的，不是新阈值）：

| 开间（净） | 能做的形 | 不能做的形与原因 |
|---|---|---|
| < 1800 | 一字（单排，柜深可降到 500） | 双排会挤穿通道 |
| 1800–2400 | 一字；L 形需短边 ≥ 900 | 双排通道压到 [J-KIT-02] 下限以下 |
| 2400–2700 | L 形；双排刚够 [J-KIT-02] | 双排要实测门洞、冰箱位、窗台 |
| ≥ 2700 | U 形；≥ 3300 才谈 U + 岛 | 岛台归 `dining-island` |

**U 形什么时候不成立**（四条任一即放弃）：
1. 开间 < 2700：两排柜 + 端头柜吃掉 1800，通道不够；
2. 门开在长边中间：U 的一条腿被门打断，实际只剩 L；
3. 窗台低于 900 且必须做吊柜：吊柜会压窗 [J-WIN-01]；
4. 进深 < 2100：两个转角之间只剩一条 600 的缝，人进不去。

**第 2 步 · 压操作三角** [J-KIT-01]
先落位"冰箱 → 水槽 → 灶台"三点，再谈柜子。三点都取**使用面中心**（不是家具中心）。
- 三角三边分别量，任一边超界就换形或换位，不要靠"把冰箱往角落塞"凑；
- 三角成立后，水槽与灶台之间必须再放下一段连续台面 [J-KIT-03]。

**第 3 步 · 排备餐顺序（取 - 洗 - 切 - 炒 - 盛）** [J-KIT-03]
沿人站立的动线单向排：冰箱取出 → 水槽洗 → 切配区 → 灶台 → 盛盘区。
- 切配区放在水槽与灶台之间，这一段是唯一不能被打断的台面 [J-KIT-03]；
- 盛盘区在灶台另一侧，靠通道一端；没有空间时把微波炉/电饭煲叠到竖向高柜里，别占切配面；
- 顺序反了（切在洗之前、炒在切之前）等于每天多走两趟，宁可换形也别将就。

**第 4 步 · 吊柜与窗** [J-WIN-01]
- 吊柜底距台面 500–600、顶到 2100–2200；进深 350，浅于地柜，避免碰头；
- 窗洞范围内不做吊柜、不落冰箱与高柜 [J-WIN-01]；
- 窗台高于 900 时，窗下可以做 900 高的地柜；窗台低于 900 时窗下只能留空或做台下柜；
- 油烟机侧与窗之间至少留一段可开启的窗扇，不要把窗做成死的。

**第 5 步 · 冰箱** [J-KIT-04]
- 冰箱不与灶台正对（热气直吹冷凝器），也不紧贴灶台一侧；
- 开门侧留够开启与取物的空间 [J-KIT-04]；双开门两侧都要留散热缝；
- 冰箱不要放在通道尽头，否则开门即堵路；进深不够时选 600 深的窄体机，不要硬塞 700。

**第 6 步 · 复核通道** [J-KIT-02] [J-CIR-01]
- 单排/双排柜前按 [J-KIT-02] 留；柜门、烤箱门、洗碗机门打开时也要能站人；
- 通道里不许出现地垫、垃圾桶、折叠凳这类"临时会变永久"的东西；
- 小厨房里 700 只是应急下限 [J-CIR-01]，不是可以拿来当设计目标的值。

**第 7 步 · 分批提交与检查（不要一次改完再检查）**
1. 先提交地柜与冰箱，`scene.apply_edits` 带 `base_version`，`op_id` 唯一；
2. `check.run` 看通道、窗、重叠；
3. 再提交吊柜、油烟机、台面小家电，再检查；
4. 最多 3 轮修复 [J-VER-02]；3 轮后仍不通过的写进"未解决清单"，不要用"看起来能用"收尾；
5. 只改本次涉及的柜体与家电，户型与无关家具不动 [J-VER-01]。

## 依赖什么

| 工具 | 用途 | 状态 |
|---|---|---|
| `catalog.search` | 取柜体、冰箱、油烟机的 key 与默认尺寸 | 可 mock |
| `scene.get_snapshot` | 读墙、洞口、窗台高、房间净尺寸 | 待成员1 |
| `scene.apply_edits` | 提交增删改，带版本与幂等 | 待成员1 |
| `check.run` | 通道、挡窗、挂墙、重叠 | 可 mock |

与原项目 Skill 的差异：原流程是"描述厨房 → 生成图纸 → 脚本自查"，本技能是"读场景 → 按形定柜 → 分批提交 → 读检查报告"；柜体 key 与尺寸沿用上游目录，但**选形判断被写成一张可复核的表**，而不是散落在注释里。

未适配时的降级路径（状态仍为 `pending_adaptation`）：
- 没有 `scene.*`：用文字给坐标方案（x/y/mm）+ 开间/进深/洞口三行实测表，交主控转场景；
- 没有 `check.run`：按第 1、6 步的阈值人工核算，并在交付里注明"未经工具检查"。

## 怎么验证

- **正向** `KIT-dev-01`：2.7 × 3.3m 厨房（8.9㎡），L 形（北墙 2400 + 西墙 1500），冰箱在东南角朝西，油烟机贴北墙，微波炉落在西侧短台面上。期望 `check.run` 全通过：通道 ≥ 900、窗内侧 150 无高家具、冰箱不在窗前 400、门扇开启区干净、台面物件在支撑面上。
- **边界** `KIT-dev-02`：2.1 × 3.1m 厨房（6.5㎡）硬做双排。期望报 `CIR-02`（房间内没有 ≥ 900 的通行区）——这正是"开间 2100 不该做双排"的几何证据，技能要拒绝并把方案退回一字形。

两个案例都在 `examples/` 下，`ops.json` 可被 mock 引擎复跑；L1 结构与 L2 几何结果记录在 `manifest.validation`。
