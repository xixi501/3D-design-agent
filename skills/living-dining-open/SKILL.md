# LDK 一体大空间的分区与动线

## 什么时候用

✅ 适用：
- 使用面积 30–60㎡ 的 LDK 一体厅、大横厅、客餐厨一体；
- 场景快照里已有墙体与门窗洞口（户型图已解析成场景）；
- 用户要"分区但不要隔断""孩子要能跑开""别一进门就看见沙发背面"。

❌ 不适用（转其他技能）：
- 面积 < 30㎡ 或开间 < 4000：转 `living-dining-small`，尺度做不出三段；
- 只想加一个阅读角或工作角、全局布局不动：转 `social-reading-zone`；
- 需要砌墙、加隔断门、改水电点位：超出本技能，交回主控并说明原因 [J-STA-03]；
- 用户要"先看风格再定布局"：先走 `style-coherence`，再回到本技能。

开工前只问四件事（问不到就按保守值）：
1. 常住几口人、是否常来客——定沙发与餐桌规格；
2. 做饭频率、要不要中岛——定西厨形态；
3. 要不要在家办公 / 孩子写作业——定第三块是工作角还是西厨；
4. 电视还要不要——决定主墙归电视、收纳还是书架。

## 怎么做

**第 1 步 · 量三段**
`scene.read` 取墙与洞口，沿长边把平面切成三段候选带：入口带（靠门）、中段、采光带（靠窗或阳台）。
记下每段的净宽净深，以及每面墙的连续长度与洞口位置；连续实墙不够一段时，第三块改成工作角而不是西厨。

**第 2 步 · 先画环线，再放家具**
在平面上标出"入户门 → 每一段"的通长通道，宽度按 [J-CIR-01] 的上限取，而且要两条（东西或南北各一条）形成环线。
主通道不得从沙发与茶几之间、餐桌与椅子之间穿过 [J-LAY-01]。
[J-CIR-02] 判的是"从每扇门能不能走到主要区域"，所以环线必须在落家具之前定稿——先放家具再挤通道，必然返工。

**第 3 步 · 三段分区（不砌墙，用家具做"物理界"）**

| 区 | 定位家具 | 做"界"的方式 | 不许做的事 |
|---|---|---|---|
| 会客组 | 沙发 2200×950 + 茶几 1200×600 + 地毯 | 背靠一面实墙，两侧各留一条通长通道 | 沙发+隔断把会客区围成三面墙 |
| 用餐组 | 长桌 1600×900 + 4 椅（或 φ1300 圆桌） | 用 1.1–1.5m 的净距与相邻区拉开，不靠柜体隔 | 餐桌放在入户到会客的动线上 |
| 西厨组 | 台面 2100×600 + 冰箱 700×700 | 靠一段实墙做 L 或一字，操作面朝厅 | 台面与窗洞打架、冰箱挡门 |

分区"界"的硬规则：任何一条界，两端至少各留一条通道，界本身不得从墙连到墙——LDO-dev-02 就是反例。

**第 4 步 · 地毯与灯位（开放空间里最便宜的分区）**
- 地毯只压会客组：至少盖住主沙发前腿 [J-PROP-02]，外沿压到茶几之外，餐区不铺大块地毯（油污与绊脚）；
- 灯位按区落，而不是一盏顶灯照全场：每区一个顶灯或吊灯，会客组再加一盏落地灯，环境光/任务光/重点光三层齐 [J-LIGHT-01]；
- 分区占比：单一功能区不超过开间进深的 60%，并保留一条贯穿通道 [J-PROP-03]；
- 会客组的沙发长度不超过所在墙长的 2/3 [J-PROP-01]，不够长时用"沙发 + 单椅"而不要加长沙发。

**第 5 步 · 焦点与配色（只留一个焦点）**
视觉焦点只给一处（窗外景观、一面造型墙、或一盏大吊灯），其余造型压低 [J-STY-03]；
配色按主 60% / 辅 30% / 点缀 10% 分配，点缀色只在软装上重复两次以上 [J-COL-01]；
同厅家具走同一风格（现代/北欧/日式原木…），混风格时以硬装为准 [J-STY-01]。

**第 6 步 · 窗、门与"三成留白"**
- 窗帘盖满窗洞、两侧各多 100–200，窗帘前 150 内不放高于 600 的落地家具 [J-CUR-01]；
- 推拉/折叠门洞前 400 内不放家具 [J-DOOR-01]；
- 高于窗台的柜类不进窗前 400 [J-WIN-01]；
- 留白用可数的办法：所有落地家具的投影加起来不超过地面三成，剩下的地方必须是连续可走的整块。

**第 7 步 · 分批提交与检查**
1. 先提"分区半岛 + 会客组"，`candidate.propose` 带 `base_version`，`op_id` 唯一；
2. `candidate.preflight` 看通行与遮挡，再提"用餐组"，再检查；
3. 最后提"西厨组 + 地毯 + 灯位"，第三次检查；
4. 每轮只改被检查点到的对象，无关对象与户型不动 [J-VER-01]；
5. 自动修复最多 3 轮，3 轮后仍不通过的写进"未解决清单"交给用户，不用"看着差不多"收尾 [J-VER-02]。

## 依赖什么

本技能只使用以下语义能力（不含任何写场景权限）：

| capability | 用途 |
|---|---|
| `scene.read` | 读取当前场景/现状 |
| `catalog.search` | 检索家具库，取默认尺寸与挂墙属性 |
| `candidate.propose` | 产出候选（主系统审批后落库） |
| `candidate.preflight` | 几何与净空预检，返回问题码 |
| `candidate.review` | 复核候选与需求、判据的一致性 |
| `candidate.render` | 输出视角截图，作为验收证据 |

**边界**：不持有写权限——没有场景写入能力，也没有项目提交能力。技能只产出候选与验收意见，正式场景由主系统审批、落库与回滚。
**降级路径**：上述 capability 未接入时，输出坐标方案（mm，`at` 为家具中心）+ 验收清单，交主系统转成场景；不得声称已执行。

## 怎么验证

- **正向** `LDO-dev-01`：6000 × 8400 的方厅（内净约 47.6㎡），西厨（台面 + 冰箱）、用餐（长桌四椅）、
  会客（沙发 + 茶几 + 电视矮柜半岛 + 地毯 + 落地灯）三段。期望 `candidate.preflight` 全通过：
  半岛两端通道 2100 / 1500，矮柜东端到东墙 2200，窗内侧带无高柜，门扇区空闲。
- **边界** `LDO-dev-02`：同尺寸房间，把"分区"做成一条中岛 + 台面 + 餐边柜从西墙连到东墙的柜带。
  期望报 `CIR-02`（从门口只能到达 17% 的通行区域），技能应拒绝这种做法并给出"半岛两端留通道"的替代。

两个案例都在 `examples/` 下，`ops.json` 可被 `tools/dry_run.py` 复跑。L1 结构结果由 `tools/skill_lint.py` 出，
L2 几何结果由 `tools/dry_run.py` 出，逐条记录在 `manifest.validation`（当前仍为空：只做过本地 dry-run，
未接真工具，故状态保持 `pending_adaptation`）。
