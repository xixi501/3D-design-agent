# SRZ-dev-02 · 27㎡ 客厅（边界：书架挪到窗下）

## 输入

- 场景与 SRZ-dev-01 相同（4500 × 6000，北窗 2600，南门 900），当前已是"会客组 + 阅读组"的成品状态。
- 用户原话："书靠着窗放，白天有光，看着也好看，把书架挪到窗下面去。"

## 已知约束

- 本次任务只有一句"只动阅读角"，会客组四件仍然不能动 [J-VER-01]；
- 用户说的是"挪书架"，不是"加书架"，所以走 `move` + `rotate`，不新增对象；
- 窗是北墙那扇 2600 宽的平开窗，窗台高 600。

## 技能给出的方案（错误示范，应被拒绝）

```json
{"op":"rotate","id":"o_shelf","rot":0},
{"op":"move","id":"o_shelf","to":[1400,275]}
```

书架 900×350 转到横放后落在 (1400, 275)，实际占位 x 950–1850、y 100–450，
正好压在窗洞下沿：它高 2000，比窗台 600 高得多。

## 判定

`check.run` 必须同时报两个码，`pass = false`：

- `CUR-01`：窗内侧 150 带内出现 h>600 的落地家具——窗帘装不上、也拉不动；
- `WIN-01`：窗前 400 内有高于窗台的高柜——挡窗、挡光、挡擦窗。

技能的正确反应不是"试试看能不能通过"，而是当场拒绝并给出替代位置：
书架留在东墙、沿墙向北留出窗洞 400 带；或用矮柜（h < 窗台）替换高书架。
拒绝时一句话说明原因，并把替代方案一起给出（见 SKILL.md 第 3 步的取舍表）。
