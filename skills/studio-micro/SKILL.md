# 开间/一居多功能合一

## 什么时候用

✅ 适用：
- 开间/一居，使用面积 20–40㎡，只有一间可自由布置的屋（睡眠、会客、用餐、工作同处一室）；
- 已有含墙体与门窗的场景，或户型图已解析成场景；
- 用户说"一间当几间用""想隔出睡眠区又不想砌墙""东西太多怎么塞"。

❌ 不适用（转其他技能）：
- 面积 > 40㎡ 或本来就是 LDK 大空间：转 `living-dining-open`，那边靠家具组分区，不靠"多功能合一"；
- 需要拆墙、加隔墙、改门窗洞口：超出本技能，交回主控并说明原因；
- 出租房只做软装、不动布局：转 `rental-makeover`（可逆与预算优先）。

开工前只问三件事（问不到就按保守值）：
1. 常住几口人、是否两人作息不同（决定床宽与是否需要帘）；
2. 有没有必须保留的大件（钢琴、1.8m 床、双门衣柜）；
3. 在家工作几天/周、是否真的在家吃饭（决定桌子数量）。

## 怎么做

**第 1 步 · 先排优先级，不是先摆家具**

四件事里只有两件"不能折叠"：**睡眠**与**收纳**。所以默认顺序是：
睡眠 > 收纳 > 会客 > 用餐/工作（后两者合并到一张桌子）。
用户坚持要"大沙发 + 独立餐桌 + 书桌"时，把面积账算给他：20–28㎡ 放不下三套独立家具还留 700 通道，必须砍一件 [J-CIR-01]。
面积下限先按"兼起居的卧室"核对 [J-STA-01]：低于下限时，先说明"这间在规范上还算不算起居"，再谈布置。

**第 2 步 · 定"固定端"**

- 床：单人 1200×2000，双人 1500×2050（20–28㎡ 的上限），1800 只在 ≥32㎡ 且确认要时用；
- 衣柜：1000×600 或 2000×600，深度不超过 600；开口朝向不与床尾正对；
- 这两件贴两端墙放，让单一功能区不超过开间进深的 60%，中间自然留出一条贯穿通道 [J-PROP-03]。

**第 3 步 · 用家具做软隔断（不砌墙）**

按代价从低到高选：
1. 书架 900×350、高 2000，**垂直于长边**摆，两侧都能走；只挡视线不挡光；
2. 顶装轨道 + 布帘（落地帘要留 150 窗帘活动区 [J-CUR-01]），夜里拉上就是卧室；
3. 地台（高 ≤150）只做"视觉抬高"，不做高差，起夜会绊；
4. 玻璃/格栅隔断最后选：造价高、不可逆。

隔断只做**一道**，做两道就把开间切成了走廊。隔断到对面家具的净距必须 ≥700 [J-CIR-01]。

**第 4 步 · 折叠与可移动家具清单**

| 位置 | 固定方案 | 折叠/可移动替代 | 什么时候必须替代 |
|---|---|---|---|
| 餐桌 | 1200×800 | 折叠桌贴墙 / 吧台 800 深 | 面积 < 26㎡ 或餐桌只在周末用 |
| 会客 | 双人沙发 | 沙发床 / 白天当工作座 | 常有留宿 |
| 工作面 | 独立书桌 | 与餐桌共用 1200×800 | 在家工作 ≤2 天/周 |
| 收纳 | 满墙柜 | 带轮边柜 + 床下抽屉 | 租约 < 2 年 |

可移动件的判断标准：**一个人 10 分钟内能挪走**，且挪走后原地能恢复通行。

**第 5 步 · 视觉分区（不靠墙也要像两个房间）**

- 地毯 ≥ 2000×1700，只压会客组前腿，不铺到床下；
- 灯位分区：餐桌上方一盏吊灯、沙发侧一盏落地灯、床头一盏壁灯；不允许只有一盏顶灯 [J-LIGHT-01]；
- 顶面用局部吊顶或轨道灯"画"出会客区，比砌墙便宜且可逆。

**第 6 步 · 通道与门**

- 主通道 ≥700，且**不被床堵**：床不横在入户门与主区之间，床头不顶门；
- 门扇开启范围内清空；从每扇门都要能走到床、桌、柜 [J-CIR-02]；
- 窗内侧 150 内不放高于 600 的落地家具 [J-CUR-01]。

**第 7 步 · 提交与检查**

1. 先提交床 + 衣柜（固定端），`candidate.propose` 带 `base_version`，`op_id` 唯一；
2. `candidate.preflight` 看通道与门；
3. 再提交会客组、工作/餐桌、软隔断，分 2–3 批；
4. 最多 3 轮修复 [J-VER-02]；3 轮后仍不过的写进"未解决清单"，不要用"看起来可以"收尾；
5. 只改本次涉及的对象，户型与无关家具不动 [J-VER-01]。

## 依赖什么

本技能只使用以下语义能力（不含任何写场景权限）：

| capability | 用途 |
|---|---|
| `scene.read` | 读取当前场景（墙体、洞口、房间、已有家具） |
| `catalog.search` | 检索家具库，取默认尺寸与挂墙属性 |
| `candidate.propose` | 产出候选布置（主系统审批后落库） |
| `candidate.preflight` | 几何与净空预检，返回问题码 |
| `candidate.review` | 复核候选与需求、判据的一致性 |

**边界**：不持有写权限（无 `scene.write` / `project.commit`）。技能只产出候选与验收意见，正式场景由主系统审批、落库与回滚。
**降级路径**：上述 capability 未接入时，输出坐标方案（mm，`at` 为家具中心）+ 验收清单，交主系统转成场景；不得声称已执行。

## 怎么验证

- **正向** `STU-dev-01`：4.0×7.0m 开间（轴线 28㎡，净约 25.8㎡）。北墙入户门、东墙窗；床靠南、衣柜贴西、双人沙发与茶几在中段、1200×800 桌同时承担工作与用餐、书架垂直做软隔断。期望 `candidate.preflight` 全通过（700 通道连续、门扇与窗帘带净空、无重叠）。
- **边界** `STU-dev-02`：把 1.8m 床推到入户门内侧，想在南侧挤出 450 的床头柜位。期望报 `CIR-02`（门口落脚带被床压死，门到主区不通；同一位置也压到门扇扫掠，会同时出现 `DOOR-02`）。技能应拒绝并把床退回"床头不顶门"的位置。

两个案例在 `examples/` 下，`ops.json` 可被 `tools/dry_run.py` 复跑；L1/L2 结果回填 `manifest.validation`。
