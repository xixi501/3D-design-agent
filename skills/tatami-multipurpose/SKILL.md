# 榻榻米 / 多功能房

## 什么时候用

✅ 适用：
- 使用面积约 5–12㎡ 的房间要做榻榻米：地台下收纳、台面坐卧、兼顾书房或茶室；
- 用户说"下面能放东西、来人能睡、平时我在这儿办公/看书"；
- 已有一版含墙体与门窗的场景，或户型图已解析成场景。

❌ 不适用（转其他技能）：
- 只是普通次卧、不做地台：转 `guest-bedroom`（床的摆法与柜桌争夺是另一套判断）；
- 要做整体儿童房（成长性、安全）：转 `kids-room`；
- 地台位置压在管道井、水表、强弱电箱上：先解决检修可达，本技能不覆盖；
- 需要拆墙、加窗、改门洞：超出本技能，交回主控并说明原因。

开工前问四件事（问不到就按保守值）：
1. 这间房主要给谁用、多久用一次——决定地台占一半还是一整面；问不到按"临时客房 + 储物"做；
2. 地台下要收什么（换季被褥 / 行李箱 / 日常杂物）——决定上翻还是侧抽；问不到按侧抽做，日常可用；
3. 要不要升降桌，升起来之后还要不要走人——决定台面留多少空；
4. 门是平开还是推拉——平开门的地台退让量完全不同；问不到按平开门、留足 900 × 900 的扫地。

## 怎么做

**第 1 步 · 先定地台占多少（本技能的核心判断）**

| 用法 | 地台进深 | 剩下的地面做什么 |
|---|---|---|
| 纯客房 + 储物 | 占满整面短边或整面长边 | 门口留落尘区与通道 |
| 客房 + 书房 | 占一面墙，进深够放矮桌与坐垫 | 另一侧放书桌/柜，保住 700 通道 |
| 长期住 + 收纳 | 占一面墙，且必须有侧抽 | 升降桌或独立书桌，床不再另设 |

地台是"能站上去的家具"：它一旦落地，房间的可走面积就只剩台外那一圈。所以先算台外还剩多少，再决定台面尺寸——不要先画台、再想办法走路。

**第 2 步 · 地台高度与收纳方式**
- 低台（贴地、只做一层）优先**侧抽**：抽屉朝通道拉出，台面不用清空；
- 高台（能放下被褥/行李箱）才能**上翻**：上翻盖要求台面上方净空、且掀盖时人不能站在台面上，所以上翻格不要布置在人必经的台面中段；
- 侧抽的拉出方向必须在通道侧，且拉出时不被门扇、柜门挡住；
- 上翻格与侧抽混用时，把上翻格放在靠墙、靠角的"不常开"位置。

**第 3 步 · 地台与门扇的开启冲突（最容易翻车的一处）**
- 地台边缘必须让开平开门扇的扫掠区（门宽 × 门宽）[J-DOOR-02]；地台一做过来，门就只能开一半；
- 推拉/折叠门前 400 内同样不放家具 [J-DOOR-01 的口径]；地台压到推拉门轨道上，门直接推不动；
- 门口先做 900 宽左右的"落尘区"（不铺台），地台从门扇开启区之后起；
- 门口 300 深内要保持可落脚的自由格，不能被台体切断 [J-CIR-02]。

**第 4 步 · 升降桌与通行**
- 桌收起时台面可坐卧，桌升起后桌边到台缘、柜面之间要能过人 [J-CIR-01]；
- 台面到对面墙/柜的距离按"通道净宽"算，不要用"坐下时膝盖位置"算——坐下和走过是两件事；
- 台高与坐垫高度要配套，否则升起的桌会顶到窗台或窗帘。

**第 5 步 · 窗下地台的进深**
- 窗内侧 150 内不得有高于 600 的落地体量 [J-CUR-01]：地台面做到 600 以上时，窗帘就被台体挡住，只能改短帘或把台从窗前退开；
- 台面低于 600 时可以贴窗做（常见做法），这时窗台高度要高于台面，人才不会坐在窗扇上；
- 窗前地台不要把窗扇的开启扇挡住；内开窗要预留开启角。

**第 6 步 · 软隔断**
- 屏风、布帘、矮柜用来分段时，长件不得两端同时贴死，至少一端留出绕行口 [J-CIR-09]；
- 屏风落地就算家具，它的投影也占通道；把屏风算进通道账里，而不是当"软装不算"。

**第 7 步 · 上下台阶**
地台高按 `tatami` 的 400 记，人进出要有一级踏步或缓坡 [J-CIR-11]；踏步/缓坡要占掉通道深度，必须从净宽里扣。台阶不要正对门扇开启弧线，否则门一开就撞台阶。

**第 8 步 · 面积下限核对**
房间名叫"次卧/卧室"时按单人 5㎡、双人 9㎡ 核对；同时标"兼起居"的按 12㎡ 核对 [J-STA-01]。低于下限时不要靠"地台当床"硬凑，先报面积不足。

**第 9 步 · 提交与检查**
1. 先提交地台，`check.run` 只看门扇区与窗帘区——地台放错位置，后面全白做；
2. 再提交矮桌与坐垫（`on` 指向地台，超出台面就是支撑错误）；
3. 最后提交衣柜与屏风，检查通道是否被切；
4. 最多 3 轮修复 [J-VER-02]；3 轮后仍不通过的项写进"未解决清单"，逐条给原因与替代方案；
5. 只改本次涉及的对象 [J-VER-01]。

**第 10 步 · 常见错误与对策（榻榻米房最常返工的六种）**

| 现象 | 原因 | 对策 |
|---|---|---|
| 门只能开一半 | 地台做到门口、没让门扇 | 门口留落尘区，台从门扇开启区之后起 |
| 窗帘被台面顶住 | 台面做到 600 以上还贴窗 | 降台、改短帘，或把台从窗前退开 |
| 上翻盖打不开 | 上翻格在人站着的台面中段 | 上翻格移到靠墙、靠角的角落 |
| 抽屉拉不出 | 侧抽朝墙或朝门扇 | 抽屉一律朝通道侧 |
| 房间被切成两半 | 屏风两端都贴死 | 一端留出绕行口 [J-CIR-09] |
| 台面物件"悬空" | `on` 的物件超出台面投影 | 缩台面物件尺寸，或调整 `on` 的落位 |

## 依赖什么

| 工具 | 用途 | 状态 |
|---|---|---|
| `catalog.search` | 取 `tatami` / 矮桌 / 坐垫 / 衣柜的 key 与默认尺寸 | 可 mock |
| `scene.get_snapshot` | 读墙、洞口、房间净尺寸、门窗开启方向 | 待成员1 |
| `scene.apply_edits` | 提交增删改；台面物件带 `on` 指向地台 | 待成员1 |
| `check.run` | 门扇、窗帘、重叠、支撑面、通行 | 可 mock |

与原项目 Skill 的差异：原流程里"榻榻米多高、哪里上翻"只写在文字方案里，没人核过门扇和窗帘；本技能把地台当家具处理，让 `check.run` 能直接判它压没压门、挡没挡窗帘。

未适配时的降级路径（状态仍为 `pending_adaptation`）：
- 没有 `scene.*`：给出地台四角坐标与台面物件坐标（mm，`at` 为中心），交主控转场景；
- 没有 `check.run`：人工核算门扇扫掠区与窗内侧 150 条带，并在交付里注明"未经工具检查"。

## 怎么验证

- **正向** `TAT-dev-01`：2.8 × 3.4m 多功能房（内净约 2.6 × 3.2m，8.3㎡）。地台 2000 × 2000 贴西北角、矮台（400）贴窗、门口留落尘区、东墙衣柜、南侧屏风留绕行口。期望 `check.run` 全通过。
- **边界** `TAT-dev-02`：用户要求"地台做到门口，进门就上台阶"。地台压进 900 门扇开启区。期望报 `DOOR-02`（门扇开启），技能应拒绝并改为"门口留落尘区、地台从门扇区之后起"。

两个案例在 `examples/` 下，`ops.json` 可被 mock 引擎复跑；L1 结构与 L2 几何结果记录在 `manifest.validation`。
